## 摘要
智能体任务本质上是长时程、多轮交互的，通过与环境互动不断积累上下文。现有的上下文压缩方法不可避免地导致信息丢失，且由僵化的启发式规则触发，难以与智能体不断演化的推理焦点对齐。我们提出智能体上下文管理（ACM），该框架为智能体配备专门构建的上下文编辑工具，以实现无损上下文管理。受人类短期与长期记忆交互的启发，智能体自主决定何时压缩其上下文，将丢弃的内容卸载到外部记忆系统，并在后续需要时按需查询。基于此框架，我们进一步开发了一个后训练流水线，构建高质量上下文管理演示，并在智能体搜索与编码任务上提升模型性能。进一步分析表明，有效的上下文管理可降低峰值 token 压力，支持更深入的探索，并在独立试次中产生更一致的解决方案。代码、数据和模型检查点可从 https://github.com/lixiaochuan2020/agentic-context-management 获取。

## Abstract
Agentic tasks are inherently long-horizon and multi-turn, constantly accumulating context through interactions with the environment. Existing context compression methods inevitably incur information loss and are triggered by rigid heuristic rules, leaving them misaligned with the agent's evolving reasoning focus. We propose Agentic Context Management (ACM), a framework that equips agents with purpose-built context editing tools for lossless context management. Inspired by the interaction between short-term and long-term human memory, the agent autonomously decides when to compress its context, offloads discarded content to an external memory system, and queries it on demand for later retrieval. Building on this framework, we further develop a post-training pipeline that constructs high-quality demonstrations of context management and improves model performance on both agentic search and coding tasks. Further analysis reveals that effective context management reduces peak token pressure, enables extended explorations, and yields more consistent solutions across independent trials. Code, data, and model checkpoints are available at https://github.com/lixiaochuan2020/agentic-context-management.

## 1. 核心问题与整体含义（研究动机和背景）
- **核心问题**：长时程（long-horizon）、多轮交互的智能体任务（如搜索、编码）会持续积累大量上下文，导致智能体的上下文窗口迅速达到极限。现有上下文压缩方法存在两大缺陷：
  - **信息损失**：通过截断、摘要等方式丢弃原始内容，且无法事后恢复。
  - **触发机制僵化**：压缩由外部启发式规则（如固定 token 阈值）触发，无法与智能体自身的推理状态和任务进展对齐。
- **研究动机**：受人类认知中短时记忆与长时记忆交互的启发，让智能体像人类一样自主决定何时压缩、存储和检索上下文，实现无损且灵活的上下文管理。
- **整体含义**：提出 Agentic Context Management (ACM) 框架，将上下文管理从外部被动监控转变为智能体内部主动决策，显著提升长时程任务性能和探索效率。

## 2. 方法论：核心思想、关键技术细节、算法流程
### 核心思想
- 赋予智能体两种专用工具，模拟人类记忆机制：
  - **manage_context**：将当前窗口之前的消息压缩为简洁摘要，并将原始完整消息无损保存到外部磁盘文件（长期记忆），返回带唯一标识（summary_id）的摘要。
  - **query_memory**：通过 summary_id 查询外部存储的原始消息，精确检索所需信息。
- 智能体在推理过程中**自主决定**何时调用这些工具，而非依赖外部触发器。

### 关键技术细节
- **框架设计**：
  - 智能体保持一个短期的“工作记忆”（in-context 消息），专注于当前推理。
  - 当智能体认为上下文冗余或接近饱和时，调用 `manage_context` 将历史消息压缩并卸载，保留摘要。
  - 后续需要具体信息时，通过 `query_memory` 按需检索原始内容。
- **后训练流水线（Data Generation）**：
  - 采用教师-学生框架，结合**双重约束**生成高质量训练数据。
  - 阶段1：学生模型在两种条件下进行 rollout：有上下文管理工具（生成轨迹 H⁺）和无工具（生成轨迹 H⁻）。
  - 阶段2：教师模型审查轨迹并注入/修改操作：
    - **注入约束**（在 H⁻ 上）：教师识别学生陷入循环、冗余查询或累积过多上下文的时机，插入 `manage_context` 调用。
    - **修正约束**（在 H⁺ 上）：教师识别学生过早压缩或压缩不合适的时机，替换为更合适的行动（如继续搜索、获取文档或提交答案）。
  - **损失函数**：学生模型通过 on-policy 蒸馏优化，匹配教师模型在 top-K 候选 token 上的软分布。损失定义如下（论文公式）：

- **质量过滤**：

## 6. 主要结论与发现
- ACM 框架在所有三个基准上显著优于 ReAct 和 Summary Agent 基线。
  - 在 BrowseComp-Plus 上，ACM-Post-Trained 相对 ReAct 提升 27%（57.0% → 72.7% Pass@1）。
  - 在 DeepSearchQA 上提升 16%（36.7% → 42.5%）。
  - 在 SWE-Bench Verified 上提升 8%（48.9% → 53.0%）。
- **关键技术贡献**：
  - **无损压缩**：原始消息保存至外部存储，可精确检索，避免信息永久丢失。
  - **智能体自主决策**：压缩时机由智能体自身推理状态驱动，而非硬性阈值。
  - **后训练有效**：基于双重约束的蒸馏数据能够教会模型何时压缩、何时不压缩，稳定提升性能。
- **行为分析揭示**：
  - ACM 智能体在上下文接近限制前主动压缩，形成锯齿状增长曲线（图3）。
  - 压缩使智能体能够进行更多探索性步骤（工具调用次数增加，峰值 token 降低）。
  - 训练后模型使用管理工具的频率更高，同时搜索和获取文档的次数也更多，表明更主动的探索。
  - Pass K（所有试次都成功）相对 Pass@K 提升更显著，说明上下文管理提高了解决方案的**一致性**。

## 7. 优点
- **创新性**：首次将上下文管理作为智能体自主决策的显式动作，而非外部启发式规则，符合人类记忆机制。
- **无损性**：通过外部存储保留原始内容，支持事后精准检索，克服了摘要压缩的信息损失问题。
- **双约束训练数据生成**：教师注入+修正的双重约束能高效产生高质量、覆盖正反例的上下文管理演示，无需繁重的强化学习。
- **开源**：公开代码、数据以及训练数据生成流水线，推动社区复现和改进。
- **广泛的实验验证**：覆盖搜索和编码两种典型长时程任务，行为分析和消融实验充分揭示了机制的运作原理。
- **性能提升显著**：在 BrowseComp-Plus 上近乎匹配 40× 更大的开源模型；在峰值 token 压力方面也优于 Summary Agent。

## 8. 不足与局限
- **依赖强基模型**：ACM 框架要求基座模型本身具备强长时程推理和工具使用能力。小型或脆弱模型（如 Qwen3-4B-thinking）无法产生足够长的轨迹来利用上下文管理，导致无法受益（附录 D）。
  - 这意味着 ACM 的收益在弱模型上可能不适用，限制了通用性。
- **基线复现差异**：由于部分前期基线（如 Mem1、SUPO、AgentFold）的评估设置不同且未完全开源，作者重新实现了 ReSum、ACON、ACE 等基线。尽管尽力遵循原设计，但可能存在微小实现差异，影响公平对比（Limitations 部分明确提及）。
- **算力资源描述不足**：未提供训练过程的 GPU 型号、数量、时长等信息，不利于复现和成本评估。
- **训练数据生成成本高**：需要运行教师模型（397B）进行标注，计算开销较大。虽然作者已开源数据，但自主生成仍需大量资源。

- **可能引入误用**：自主压缩可能在不恰当的时候被触发（如过早压缩关键信息），尽管训练试图避免，但在长尾分布下仍有可能发生。
