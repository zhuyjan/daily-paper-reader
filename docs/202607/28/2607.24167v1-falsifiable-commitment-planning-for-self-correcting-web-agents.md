## 摘要
长周期网络代理常常在最终失败前就已偏离轨道：即使当前状态、复用的技能或规划假设不再支持用户指令，轨迹仍可能在局部看似合理。现有代理能够规划、反思或复用经验，但其规划很少明确说明在何种证据下仍应信任当前步骤。我们提出FCPAgent，一个可证伪承诺规划框架，用于构建鲁棒的长周期网络代理。FCPAgent将每个规划步骤表示为一个可证伪承诺单元（FCU）：一个基于可复用技能的子目标，附带确认证据、证伪证据和置信度分数。执行过程组织为规划-测试-修复循环。混合承诺测试模块在候选动作修改浏览器前对其进行检查，并在执行后观察结果；为提升效率，它结合了轻量级证据匹配与基于LLM的诊断验证。当证据证伪一个承诺时，范围感知修复将矛盾定位到执行、技能或规划层面，并修订最小的恰当部分。在WebArena上，FCPAgent相较于最强基线实现了13.8%的平均成功率相对提升，在长周期任务上尤其获得了巨大增益。

## Abstract
Long-horizon web agents often go off track before final failure: a trajectory can remain locally plausible even after the current state, reused skill, or plan assumption no longer supports the user instruction. Existing agents can plan, reflect, or reuse experience, but their plans rarely specify the evidence under which an active step should still be trusted. We propose FCPAgent, a falsifiable commitment planning framework for robust long-horizon web agents. FCPAgent represents each plan step as a Falsifiable Commitment Unit (FCU): a subgoal grounded in a reusable skill, together with confirming evidence, falsifying evidence, and a confidence score. Execution is organized as a plan-test-repair loop. The hybrid commitment testing module checks candidate actions before they modify the browser and checks observations after execution; for efficiency, it combines lightweight evidence matching with LLM-based diagnostic verification. When evidence falsifies a commitment, scope-aware repair localizes the contradiction to the execution, skill, or planning level and revises the smallest adequate part. On WebArena, FCPAgent achieves a 13.8% relative improvement in average success over the strongest baseline, with especially large gains on long-horizon tasks.

## 2. 论文提出的方法论：核心思想、关键技术细节

### 核心思想
- **可证伪承诺规划（Falsifiable Commitment Planning）**：每个计划步骤被建模为**可证伪承诺单元（FCU）**，不仅包含子目标和可选技能，还显式定义了**确认证据**（当步骤有效时应观察到的信号）和**证伪证据**（何时应停止信任该步骤）。执行通过**计划-测试-修复循环**进行：先进行混合承诺测试，若证据被证伪，则通过范围感知修复来修正最小受影响部分。

### 关键技术细节
1. **Falsifiable Commitment Unit (FCU)**
   - 形式化定义：\( c_i = (g_i, s_i, E^+_i, E^-_i, \kappa_i) \)
     - \( g_i \)：子目标
     - \( s_i \)：可选链接的可复用技能
     - \( E^+_i \)：确认证据，分为前提、进展、完成三阶段
     - \( E^-_i \)：证伪证据，分为执行级、技能级、规划级三层次
     - \( \kappa_i \)：置信度（0~1）
   - 提供运行时测试与修复的共享诊断接口。

2. **计划生成（Falsifiable Commitment Generation）**
   - 离线构建**技能库**（从成功轨迹中提炼）和**失败-修复记忆库**（从失败/修复轨迹中提炼）。
   - 在线检索相关技能和失败案例，由 LLM 规划器生成紧凑的 FCU 序列 \( C = (c_1, \ldots, c_m) \)。技能提供成功经验，失败记忆提供已知风险作为证伪线索。

3. **运行时承诺测试（Runtime Commitment Testing）**
   - **混合测试**：轻量级快速测试 + LLM 慢速诊断验证。
     - **动作级测试**：在动作执行前检查候选动作与当前 FCU 的一致性。
     - **状态级测试**：执行后检查返回的浏览器状态是否支持当前承诺。
     - 快速测试使用 NLI（DeBERTa）和图像-文本匹配（SigLIP）计算确认/证伪得分，通过阈值路由决定是否继续或升级到 LLM 诊断。
     - LLM 验证器针对完成类、高风险或模糊案例进行深层推理，返回 continue、advance 或 repair 决策及诊断信息。

4. **承诺修复（Repairing Falsified Commitments）**
   - **范围感知修复**：根据诊断的违反证据类型选择最小修复范围：
     - 执行级：保留当前 FCU，修正动作路径
     - 技能级：保留子目标，替换技能并更新相关证据
     - 规划级：重写当前 FCU 及后续受影响步骤
   - 同时考虑状态严重程度决定是否需要回退到已知安全状态。修复器会检索失败-修复库中的类似案例作为软指导。

5. **经验蒸馏**：执行后，成功轨迹被蒸馏入技能库，失败/修复轨迹存入失败-修复库，实现持续学习（但实验阶段库固定）。
