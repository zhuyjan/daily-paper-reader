## 摘要
多模态基础模型和智能体系统的最新进展推动GUI智能体从单平台任务执行向跨平台交互演进。然而，构建多平台GUI智能体仍面临挑战。一方面，高质量且可执行的跨平台交互轨迹仍然稀缺，现有数据往往存在平台覆盖有限的问题。另一方面，不同平台表现出独特的交互惯例，使得联合或持续训练容易出现行为模式混合、特定平台能力退化以及灾难性遗忘。为解决这些挑战，我们构建了Uni-GUI，一个高质量的跨平台GUI交互数据集，并提出了UI-MOPD，这是首个将多教师在策略蒸馏融入GUI智能体持续学习的方法。UI-MOPD根据当前环境动态选择特定平台的教师，并通过平台条件蒸馏将平台特定行为先验转移到共享策略中，从而在保持已有平台能力的同时适应新平台。在OSWorld和MobileWorld上的实验表明，UI-MOPD分别达到了38.2%和12.0%的任务成功率，证明了其在平衡跨平台能力保留和新平台适应方面的有效性。项目页面：https://elispectre.github.io/UI-MOPD/。

## Abstract
Recent advances in multimodal foundation models and agent systems have driven GUI agents from single-platform task execution toward cross-platform interaction. However, building multi-platform GUI agents remains challenging. On one hand, high-quality and executable cross-platform interaction trajectories are still scarce, and existing data often suffer from limited platform coverage. On the other hand, different platforms exhibit distinct interaction conventions, making joint or continual training prone to behavioral pattern mixing, platform-specific capability degradation, and catastrophic forgetting. To address these challenges, we construct Uni-GUI, a high-quality cross-platform GUI interaction dataset, and propose UI-MOPD, the first method that incorporates multi-teacher on-policy distillation into continual learning for GUI agents. UI-MOPD dynamically selects a platform-specific teacher according to the current environment and transfers platform-specific behavioral priors to a shared policy through platform-conditioned distillation, enabling adaptation to new platforms while preserving capabilities on existing ones. Experiments on OSWorld and MobileWorld show that UI-MOPD achieves task success rates of 38.2% and 12.0%, respectively, demonstrating its effectiveness in balancing cross-platform capability retention and new-platform adaptation.   Project page: https://elispectre.github.io/UI-MOPD/.

# UI-MOPD: 多平台在策略蒸馏用于持续GUI智能体学习 — 详细中文总结

## 1. 核心问题与整体含义（研究动机与背景）

- **研究背景**：多模态基础模型与智能体系统的发展推动了GUI智能体从单平台（如仅桌面或仅移动）向跨平台交互演进。真实工作流常需跨计算机应用、移动应用和网页服务，要求智能体适应异构GUI环境并保留各平台特有的交互习惯。
- **核心问题**：
  - 高质量、可执行的跨平台交互轨迹仍然稀缺，现有数据常限于单一平台，且存在无效动作、状态-动作对齐不准确等问题。
  - 桌面与移动平台的动作语义和 affordance 显著不同（例如“返回”在桌面是关闭窗口，在移动端是按下返回按钮）。直接混合多平台数据进行联合训练或模型合并会导致行为模式混合、特定平台能力退化以及灾难性遗忘——即学习新平台时丢失已学平台的行为先验。
- **研究目标**：构建一个共享的GUI智能体，能够在持续学习场景下同时适应桌面和移动平台，既保持已有平台能力，又能有效迁移到新平台。

## 2. 方法论：核心思想、关键技术细节

### 2.1 核心思想
首次将**多教师同策略蒸馏（Multi-Teacher On-Policy Distillation, MOPD）**引入持续GUI智能体学习。通过平台条件路由，让不同平台的学生 rollout 分别与对应平台的专家教师进行反向KL对齐，从而在共享策略中保留各平台独特的行为锚点，避免异质交互信号在优化中被无差别混合。

### 2.2 技术细节

- **Stage 1 — 监督微调（SFT）**：在Uni-GUI数据集上分别对桌面和移动平台轨迹进行SFT，训练得到两个独立专家教师：桌面教师 πᵈ_ref 和移动教师 πᵐ_ref。教师模型基于Qwen3-VL-32B-Thinking。
- **Stage 2 — 多教师同策略蒸馏**：
  - **学生模型**：基于Qwen3-VL-8B-Thinking初始化，通过在线强化学习采样 rollout。
  - **平台条件教师路由**：根据 rollout 所属平台（桌面/移动），路由到对应的专家教师计算 KL 散度：
    ```
    πⁱ_ref = πᵐ_ref（若 sᵢ ∈ S_mobile），πᵈ_ref（若 sᵢ ∈ S_desktop）
    ```
  - **同策略KL估计**：使用K3估计器，仅需学生和教师对采样 token 的对数概率，计算无偏、低方差的 token 级 KL 散度：
    ```
    δⁱ_t = log π_ref(yₜ|hₜ) - log π_θ(yₜ|hₜ)
    ρⁱ_t = exp(δⁱ_t)
    D̂_KL(t,i) = ρⁱ_t - δⁱ_t - 1
    ```
  - **自适应KL掩码**：当某个 prompt 组已获得足够高的奖励（超过阈值 τ_KL）时，移除该组 rollouts 上的教师 KL 惩罚，避免过度限制探索。
  - **奖励设计**：结构化结果奖励，基于动作 JSON 中各维度（动作类型、坐标、方向、文本等）的匹配分数 fₐ ∈ [0,1]。匹配得1.0，部分匹配得 -0.5，无效动作得 -1.0。
  - **训练目标**：结合剪辑策略优化（PPO风格）与 MOPD 辅助损失：
    ```
    L(θ) = L_PG(θ) + β L_MOPD(θ)
    ```
    其中 β 控制蒸馏强度，L_MOPD 为带自适应掩码的 token 级 KL 项。

### 2.3 总体算法流程（文字说明）
1. 收集桌面和移动端的高质量轨迹（通过统一数据收集平台）。
2. 在Uni-GUI上分别SFT训练桌面教师和移动教师。
3. 学生模型从Qwen3-VL-8B-Thinking初始化，在混合平台提示上采样 rollout。
4. 按平台标签路由到对应教师，计算 token 级 KL 散度（K3估计器）。
5. 结合强化学习（GRPO变体）与MOPD损失更新学生模型，自适应移除高奖励样本的KL约束。

## 6. 主要结论与发现

- **UI-MOPD在OSWorld上达到38.2%，在MobileWorld上达到12.0%**，相比基础模型（Qwen3-VL-8B-Thinking）分别提升4.3和4.3个百分点，相对提升12.7%和55.8%。
- **优于直接混合策略**：Mixed-SFT和模型合并（权重平均/TIES）在MobileWorld上显著下降（6.4%/6.8%/0%），而UI-MOPD达到12.0%，证明平台条件蒸馏能有效避免行为模式混合。
- **保留跨平台能力**：UI-MOPD在AndroidControl⋆上提升至80.05%（合并降至74.01%），在grounding基准上基本保持甚至微增（如OSWorld-G从52.13%到52.84%），说明蒸馏方式比参数合并更鲁棒。
- **单平台SFT导致另一平台能力丧失**：专门在OSWorld上SFT后MobileWorld掉至0%；专门在MobileWorld上SFT后OSWorld提升有限。UI-MOPD同时提升双平台。
- **平台条件路由是关键**：通过不同教师分别约束桌面和移动rollout，使政策优化过程中保留各自交互先验。

## 7. 优点

- **方法创新**：首次将多教师同策略蒸馏引入GUI智能体持续学习，解决了多平台行为模式混合与灾难性遗忘问题。
- **数据贡献**：构建了Uni-GUI高质量跨平台数据集（约11.5K轨迹），并提供统一数据收集平台与清洗流程，可复用。
- **平台条件蒸馏设计**：通过路由与自适应KL掩码实现精细控制，既促进跨平台知识迁移，又避免过度约束。
- **实验全面**：涵盖交互式任务、静态理解、grounding，对比多种集成策略，消融分析验证平台条件蒸馏的有效性。
- **规模合理**：使用8B学生模型即取得优于多种更大模型（如32B/72B）的平衡性能，表明方法效率高。
- **代码与数据开源**（GitHub、Hugging Face、主页）。

## 8. 不足与局限

- **平台覆盖有限**：仅含桌面和移动两种平台，未探索Web、TV、车载等GUI环境。跨平台泛化性需进一步验证。
- **持续学习设置简化**：实验以联合训练（同时混合桌面和移动数据）为主，未展示真正的顺序学习（先学桌面再学移动）下的遗忘曲线与重放策略。
- **奖励设计依赖规则**：结构化奖励需要预先定义动作维度和匹配规则，可能难以覆盖复杂、模糊或依赖上下文的操作（如拖拽、多步手势）。
- **教师模型规模不对称**：使用32B教师蒸馏8B学生，未测试更小教师（如同规模）或更多教师（如不同平台各一个）的影响。
- **数据集偏差风险**：Uni-GUI主要由Kimi-K2.6和Gemini-3.1-Pro收集，可能引入其偏好或领域偏向；清洗依赖单一模型判断成功与否，可能存在误判。
- **计算成本较高**：需要64块H100进行训练，对于资源有限的团队不太可负担。
