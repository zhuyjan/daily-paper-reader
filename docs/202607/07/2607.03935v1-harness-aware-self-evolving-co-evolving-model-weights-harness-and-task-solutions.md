## 摘要
自演化框架通常优化任务解决方案，同时将周围的装备视为固定不变。我们提出了感知装备的自演化（HASE），一种智能体强化学习框架，其中单一模型可以在多轮动作空间中生成任务解决方案或编辑选定的装备组件。HASE使得单个Qwen3-8B模型能够匹配使用Claude Code作为装备提议者的GPT-OSS-120B模型的文本分类性能。在阿尔法因子挖掘中，HASE超越了已报道的GPT-OSS-120B基线。HASE还修复了不完美的评估组件，并在圆填充算法发现中收敛到最先进的性能。这些结果表明，HASE通过统一的智能体过程改进了装备和解决方案。

## Abstract
Self-evolving frameworks usually optimize task solutions while treating the surrounding harness as fixed. We introduce Harness-Aware Self-Evolving (HASE), an agentic reinforcement-learning framework in which a single model can generate task solutions or edit selected harness components in a multi-turn action space. HASE enables a single Qwen3-8B model to match the text-classification performance of a GPT-OSS-120B model that uses Claude Code as the harness proposer. In alpha factor mining, HASE outperforms the reported GPT-OSS-120B baseline. HASE also repairs imperfect evaluation components and converges to state-of-the-art performance in circle-packing algorithm discovery. These results show that HASE improves the harness and the solution through one unified agentic process.

### 论文总结：Harness-Aware Self-Evolving (HASE)

#### 1. 核心问题与研究动机

*   **核心问题**：现有的自演化系统（Self-Evolving Systems）普遍存在一个关键假设：将系统中的外围组件（Harness，如提示词、记忆、上下文检索策略、评估器等）视为固定不变的，仅针对任务本身的解决方案（如代码、策略）进行优化。这种“固定装备”假设限制了系统的整体性能。
*   **局限性**：
    *   **不完美的评估器**：人工编写的评估器可能不完整或与外部真实环境目标不一致，模型可能会利用这些漏洞而不是真正解决问题（奖励黑客行为）。
    *   **低效的引导组件**：固定的提示词、记忆和检索策略可能提供较差的搜索先验，导致模型难以找到最优解。
*   **研究动机**：论文旨在打破这一限制，提出一个允许系统在演化任务解决方案的同时，也能主动改进其自身工作环境（装备）的新型框架。

#### 2. 方法论：HASE算法

*   **核心思想**：HASE（Harness-Aware Self-Evolving）是一个基于强化学习（RL）的智能体框架。它允许**同一个模型**在一个统一的、**多回合（multi-turn）的动作空间**中，既可以生成任务解决方案，也可以编辑选定的装备组件。该框架通过一个**分阶段（Phase-level）的审查机制**来确保装备编辑的安全性和有效性，防止奖励黑客行为。
*   **关键技术细节**：
    *   **两类装备**：
        1.  **引导组件（Guidance Components）**：包括提示词、记忆格式化、上下文检索脚本等。其目的是改进搜索过程。HASE可以自由地改进这些组件。
        2.  **评估组件（Evaluation Components）**：包括验证器和评分器，定义了任务的有效性和指标。对这些组件的编辑被锚定在**真实世界评估器**的反馈上，防止无限制的奖励篡改。
    *   **统一动作空间**：模型在每次迭代中可以执行的动作包括：
        *   提交一个任务解决方案（如生成一个alpha因子）。
        *   使用沙盒命令（如 `ls`, `cat`, `replace`）检查和编辑装备组件。
    *   **算法流程（文字描述）**：
        1.  **初始化**：初始化模型策略、装备和可选的不匹配集。
        2.  **多阶段循环**：算法在多个阶段（Phase）中运行，每个阶段包含多个GRPO（一种RL算法）轮次。
        3.  **轨迹生成**：在每个轮次中，模型基于当前环境和装备，进行多回合交互并生成轨迹。轨迹最终必须提交一个解决方案。
        4.  **奖励设计**：
            *   **引导组件**：奖励间接来源于因装备改进而获得的更高任务分数。只有产生积极效果的编辑才被纳入候选池。
            *   **评估组件**：只有当代理分数（来自本地评估器）与真实分数（来自真实评估器）产生分歧时，修复该分歧的编辑才能获得奖励。
        5.  **分阶段审查**：
            *   **引导组件**：在每个阶段结束时，审查候选池中的装备编辑，并根据验证集性能，提交表现最好的一个固定下来，供下一阶段所有轨迹使用。
            *   **评估组件**：同样在阶段边界，查询真实评估器，发现新的代理-真实分数分歧（不匹配）案例，并据此审查评估器的修复补丁。只有当补丁在当前所有已知不匹配案例上修复了分歧，并且没有回归问题，才会被提交。
