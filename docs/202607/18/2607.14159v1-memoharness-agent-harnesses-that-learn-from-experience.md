## 摘要
智能体操控框架是外部控制层，通过管理上下文、工具、编排、记忆、解码和输出处理，将基础大语言模型转化为可执行智能体。虽然操控框架的设计强烈影响智能体行为，但大多数自动改进方法优化的是提示、流程或工作流等更狭窄的工件，而部署的智能体通常对所有情况重复使用单一的全局操控框架。我们提出MemoHarness，一种从自身执行中学习的自适应操控框架优化方法。MemoHarness将操控框架分解为六个可调控制维度，将每例诊断和提炼的全局模式存储在双层经验库中，并利用检索到的经验（无需测试时标签、反馈或额外搜索）使学习到的操控框架适应每个测试用例。在shell智能体、代码生成和分析推理基准测试中，MemoHarness相较于我们比较的固定操控框架有所改进，并展现出对未见套件和基础模型的选择性迁移。当大部分检索到的经验可缓存时，其额外上下文也能保持成本竞争力。这些结果表明，执行经验是构建比单一静态配置更具适应性的智能体操控框架的实用基础，而关于统计鲁棒性和组件归因的更广泛结论则留待未来研究。

## Abstract
An agent harness is the external control layer that turns a base LLM into an executable agent by managing context, tools, orchestration, memory, decoding, and output handling. While harness design strongly affects agent behavior, most automatic improvement methods optimize narrower artifacts such as prompts, pipelines, or workflows, and deployed agents usually reuse a single global harness for all cases. We introduce MemoHarness, an adaptive harness optimization framework that learns from its own executions. MemoHarness decomposes the harness into six editable control dimensions, stores per-case diagnoses and distilled global patterns in a dual-layer experience bank, and adapts the learned harness to each test case using retrieved experience without test-time labels, feedback, or additional search. In our evaluation across shell-agent, code-generation, and analytical-reasoning benchmarks, MemoHarness improves over the fixed harnesses we compare against and shows selective transfer to unseen suites and base models. Its additional context can also remain cost-competitive when much of the retrieved experience is cacheable. These results provide evidence that execution experience is a practical substrate for building agent harnesses that are more adaptive than a single static configuration, while leaving broader claims about statistical robustness and component attribution to future work.

## 2. 方法论：核心思想、关键技术细节、算法流程

- **核心思想**：将操控框架分解为六个可编辑的控制维度（上下文组装、工具交互、生成控制、编排、记忆管理、输出处理），构建双层经验库（每例执行记录+全局宏观模式），在训练阶段通过搜索学习一个全局基础操控框架，在测试阶段基于检索相似案例和模式，将其自适应调整为针对当前案例的个性化操控框架，整个过程无需测试时标签、反馈或额外搜索。

- **关键技术细节**：
  - **六维操控空间 (Six-Dimensional Harness Space)**：按推理时间流分解为6个维度，每个维度包含一组可编辑选项，将整体优化转化为结构化编辑。
    - D1 上下文组装：构建模型输入（指令、约束、检索材料、示例等）
    - D2 工具交互：控制何时以及如何调用外部工具或检索器
    - D3 生成控制：解码参数（最大token数、温度、候选数等）
    - D4 编排：工作流拓扑（单次调用 → 计划/执行/细化等）
    - D5 记忆管理：跨调用状态持久化（上下文摘要、丢弃陈旧状态等）
    - D6 输出处理：后处理（提取答案、验证模式、回退等）
  - **双层经验库 (Dual-Layer Experience Bank)**：由两部分组成：
    - **案例级经验 (E_t)**：存储每次搜索过程中每例的执行记录，包括配置、轨迹、奖励、代价、诊断信息（成功/失败、首要失败维度、次要维度、自然语言分析）。
    - **全局模式 (G_t)**：每隔N轮执行一次蒸馏，从失败簇中提取跨案例的规律（描述现象、证据、预期修复效果）。
  - **训练阶段优化 (Phase A - Search)**：
    - 从最小操控框架初始化（无示例、无工具、确定性解码、无记忆、直接输出）。
    - 每轮控制器根据当前操控框架和经验库构造查询，检索相关证据，提出下一个候选操控框架。
    - 在所有训练案例上执行候选框架，收集轨迹、奖励和代价。
    - 采用**正确性优先选择**：通过词序排序，先按平均奖励降序，再按平均token花费（次级代价）升序。
  - **测试阶段自适应 (Phase B - Test-Time Case Adaptation)**：
    - 对于每个新测试案例，利用冻结的经验库：
      - 通过指令嵌入余弦相似度检索最相似的**成功案例**和**失败案例**。
      - 同时检索与测试案例特征相关的全局模式。
      - 控制器基于这些证据，将全局操控框架适配为案例特定操控框架。
    - 执行该案例特定框架，产生最终输出。不涉及任何迭代反馈、搜索或学习。
  - **正确性优先排序规则**：奖励为主，执行代价（token总数）仅作为次要找平。

## 6. 主要结论与发现

- **RQ1 (绝对性能提升)**：MemoHarness在Terminal-Bench上达到0.806，超过最强基线Codex的0.722（+0.084），比其他基线高出0.250-0.445。
- **RQ2 (优化演进)**：最终选择框架在所有三个基准上均优于初始基础框架（Terminal-Bench: 0.722→0.806；LiveCodeBench: 0.900→0.967；FinanceAgent: 0.600→0.767），但在LiveCodeBench上饱和较快。
- **RQ3 (跨数据集迁移)**：学到的操控框架表现出**选择性正迁移**，尤其来自Terminal-Bench的框架给MMMU (+0.030)、StrongReject (+0.030)、SWE-Bench Pro (+0.059)带来提升。在已饱和的基准（HumanEvalFix、Reasoning-Gym-Easy）上无变化。
- **RQ4 (跨模型迁移)**：将GPT-5.3-Codex搜索出的框架直接应用到6个额外模型上，**所有模型均有提升**，平均增益+0.098，范围+0.038（GPT-4.1）至+0.233（GLM-5）。

## 7. 优点

- **结构化分解**：将操控框架分解为六个独立维度，使搜索和诊断更具针对性，避免了作为单一不透明对象优化。
- **经验积累与重用**：双层经验库不仅存储评分，还存储每例诊断和全局模式，使后续迭代不再是盲目的标量优化，而是基于知识的导向。
- **测试时自适应无标签**：无需测试时任何反馈或额外搜索，仅靠历史经验即可自适应，适合部署场景。
- **正确性优先原则**：奖励优先于成本，避免搜索偏向“便宜但错误”的配置。
- **跨数据集/模型迁移**：验证了学到的操控框架具备一定的泛化性，不仅限于源任务/模型。
- **成本可控**：通过经验缓存，额外检索开销可被抵消，在保持高精度的同时未导致成本失控。

## 8. 不足与局限

- **统计严谨性不足**：主要结果仅有点估计，无置信区间或假设检验，尤其是在小样本（18个任务）上结论的可靠性有待更大规模确认。
- **实验覆盖有限**：
  - 主要比较在Terminal-Bench上，其他两个基准仅用于展示优化轨迹，未与多基线对比。
  - 与商业系统（Claude Code等）的比较并非纯净的“操控框架”对比，无法剥离模型和工具差异。

- **未考虑在线经验积累**：当前工作限于一次训练后冻结经验库，实际部署中持续积累经验可能进一步提升。
