## 摘要
工具利用使大语言模型（LLM）智能体能够与现实世界交互并解决复杂任务。然而，现有智能体框架主要依赖由细粒度原子动作（例如基本的文件I/O或单轮搜索）组成的静态工具集，这迫使智能体为每个重复的工作流重新发明底层逻辑，导致推理开销增加和失败率上升。在本研究中，我们提出智能体可以通过将这些原子动作综合成可复用的标准操作流程（SOP）来实现自我进化，这些SOP作为可调用的高阶工具，封装了多步逻辑。我们进一步引入了EvoSOP框架，该框架使智能体能够从执行轨迹中提取SOP，并通过构建、合并、评估和修剪的系统化生命周期迭代优化工具集。大量实验表明，与基线相比，EvoSOP显著提升了任务成功率，同时大幅减少了交互轮数。我们的分析还揭示，迭代式工具优化促进了可靠且高效的工具使用模式，为开发自进化智能体提供了一条可扩展的路径。

## Abstract
Tool utilization enables Large Language Model (LLM) agents to interact with the real world and resolve complex tasks. However, existing agent frameworks predominantly rely on static toolsets composed of granular atomic actions (e.g., basic file I/O or single-turn search), which forces agents to reinvent low-level logic for every recurring workflow, leading to increased reasoning overhead and failure rates. In this study, we propose that agents can achieve self-evolution by synthesizing these atomic actions into reusable Standard Operating Procedures (SOPs), which function as callable higher-order tools that encapsulate multi-step logic. We further introduce EvoSOP, a framework that empowers agents to extract SOPs from execution trajectories and iteratively optimize the toolset through a systematic lifecycle of construction, merging, evaluation, and pruning. Extensive experiments demonstrate that EvoSOP significantly boosts task success rates while substantially reducing the number of interaction rounds compared to baselines. Our analysis also reveals that iterative tool optimization fosters reliable and efficient tool-use patterns, providing a scalable pathway for the development of self-evolving agents.

## 1. 核心问题与整体含义（研究动机与背景）

- **现状与问题**：现有LLM智能体框架普遍依赖由细粒度“原子动作”（如文件I/O、单轮搜索）组成的**静态工具集**。每当处理重复性工作流时，智能体不得不重新编排低级逻辑，导致**推理开销大、错误率上升**，缺乏人类问题解决中“分层次、可复用”的高效模式。
- **核心矛盾**：工具生成的已有工作（如ASI、CRAFT）多为一次性操作，缺乏对工具集的长期管理，造成工具集臃肿、噪声累积，反而降低代理性能。
- **研究目标**：提出一种**自进化**范式，使智能体能够从自身执行轨迹中提取、合成、优化**可复用的标准操作流程（SOP）**，从而实现对工具集的迭代式、系统化优化，提升任务成功率并压缩推理轮数。

## 2. 方法论：EvoSOP框架

- **核心思想**：将原子动作序列抽象为高阶、可调用的SOP（封装多步逻辑，类似人类SOP），并通过**构建→合并→评估→剪枝**的闭环生命周期持续优化工具集。该方法不修改底层LLM参数，属于**非参数结构优化**。
- **关键技术细节**：
  - **Constructor（构造器）**：从历史执行轨迹中提取频繁、强耦合的连续动作片段，通过LLM重写为可执行函数（含条件判断、错误处理）。
  - **Merger（合并器）**：分析新生成的SOP之间的功能重叠，将冗余步骤合并为通用性更强的高阶SOP，但保留原SOP直到验证阶段（非破坏性策略）。
  - **Evaluator（评估器）**：将新SOP加入工具集，让代理重新执行所有训练任务，捕获每个SOP的实际调用效果（成功/部分成功/失败等）。
  - **Reviewer（审查器）**：基于评估轨迹，为每个SOP标注执行状态（最优执行、部分效用、负面干扰等），据此剪枝低质量或高风险的工具。
- **与机器学习流水线的类比**：
  - 训练任务 → 数据获取
  - 当前工具集执行任务 → 前向传播
  - 轨迹分析 → 后向传播（符号化梯度）
  - 合并与剪枝 → 正则化与学习率衰减
- **整体流程**：
  1. 将初始轨迹分批次输入Constructor，生成一批SOP。
  2. Merger合并重叠SOP。
  3. 代理用更新后工具集重新执行全部训练任务（Evaluator）。
  4. Reviewer分析调用记录，删除失败率高或冗余的工具。
  5. 迭代多次（论文中实验迭代10轮），存档每次的检查点，选择训练成功率最高的轮次作为最终工具集。

## 6. 主要结论与发现

- EvoSOP**显著提升任务成功率**（ACEBench上提升2.5%~13.4%），同时**大幅减少交互轮数**（图2显示回合数从约7轮降为5轮左右）。

- **轻量级维护**：最终维持的SOP数量通常少于10个，形成了“小而精”的工具集。
- 案例研究展示了三种SOP生命周期模式：基础型（长期存在）、瞬发型（快速剪枝）、合并型（由专更新为通用）。

## 7. 优点

- **方法创新**：将自进化概念从参数更新扩展到**非参数工具结构优化**，提出完整的“构建-合并-评估-剪枝”生命周期的闭环框架，优于一次性工具生成方法。
- **模型无关性**：不改变LLM参数，兼容黑盒模型，易于集成到现有代理系统。
- **可解释性**：Reviewer对每个SOP的执行状态进行自然语言标注，剪枝理由可追溯。
- **鲁棒性**：通过检查点机制选择最优迭代，避免单次优化偏差；跨多个骨干模型验证稳定性。
- **实验全面**：覆盖多种基准、多模型、多模块消融，证据充分。

## 8. 不足与局限

- **训练数据规模较小**：仅使用25条轨迹进行SOP提取，未验证在更大规模或更复杂领域的扩展性。
