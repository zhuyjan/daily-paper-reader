## 摘要
生产环境中的LLM智能体常常因每个请求都重复生成相同程序步骤的代码而导致延迟和可靠性问题。我们用一个智能体的工具制作流水线取代了这种推理时的编码循环，该流水线在部署前将重复的标准操作流程步骤编译为经过验证、带有版本的工具。工具制作器在实时环境中进行综合，通过收集执行轨迹、观察后端模式与数值、生成候选工具，并针对标注案例进行修复。在运行时，生产智能体直接调用这些工具，仅在必要时才回退到代码生成。我们在一个履约中心告警分类系统中部署了该方法，该系统中的智能体需根据跨越异构度量后端的44节点标准操作流程对告警进行诊断。在生产中，工具调用将p50延迟降低了42%。在1500条历史告警上，通过抑制重复步骤间的运行差异，端到端错误率降低了高达53%。由于工具返回紧凑的结构化判定，它们还实现了更简单的直接调用架构，在受控消融实验中进一步将p50延迟降低了62%。版本化工具还提高了可审计性，并暴露了规范的缺失与上游数据漂移。我们的结果表明，自演化智能体可以使工业LLM系统更快、更可靠、更易于操作。

## Abstract
Production LLM agents often waste latency and reliability by regenerating code for the same procedural steps on every request. We replace this inference-time coding loop with an agentic tool-making pipeline that compiles repeated SOP steps into validated, versioned tools before deployment. The tool-maker grounds synthesis in the live environment as it collects execution traces, observes backend schemas and values, generates candidate tools, and repairs them against labeled cases. At runtime, the production agent calls these tools directly and falls back to code generation only when needed. We deploy the approach in a Fulfillment Center alarm-triage system, where an agent diagnoses alarms against a 44-node SOP over heterogeneous metric backends. In production, tool calls reduce p50 latency by 42%. On 1,500 historical alarms, they reduce end-to-end error rate by up to 53% by suppressing run-to-run variance in repeated steps. Because tools return compact structured verdicts, they also enable a simpler direct-call architecture, reducing p50 latency by a further 62% in a controlled ablation. Versioned tools also improve auditability and expose specification gaps and upstream data drift. Our results show that self-evolving agents can make industrial LLM systems faster, more reliable, and easier to operate.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **核心问题**：生产环境中的LLM智能体在每次请求时，针对相同的标准化操作流程（SOP）步骤重复生成代码，导致高延迟（推理计算开销大）、低可靠性（运行间方差大，易出错）以及高昂的算力成本。这种“推理时代码生成”范式（CodeAct风格）适合一次性任务，但在重复性工业工作流中效率低下。
- **研究背景**：现有工作包括单次工具合成、基于环境或测试的迭代构建、以及将运维文档转化为工具。但缺乏在真实生产环境中将SOP编译为经过环境接地和验证的工具，并部署到延迟敏感系统中的实际案例。
- **整体含义**：论文提出一种“自演化智能体”范式——智能体离线积累经验，将重复步骤预编译为可复用的版本化工具，运行时直接调用，仅在工具缺失或失败时回退到代码生成。这能在保持灵活性的同时大幅提升工业系统的速度、可靠性和可操作性。

## 2. 方法论：核心思想与关键技术细节

- **核心思想**：离线工具制作流水线将44个SOP决策节点逐一编译为确定性的工具函数（统一输入/输出），运行时智能体直接调用工具返回判定（true/false/no data），避免每次生成代码。
- **关键组件与流程**：
  - **数据收集子智能体**：对每个节点，运行一次基线CodeAct子智能体（访问生产MCP），收集执行轨迹（查询代码、MCP响应、观察到的模式）和分级判定。这为工具制作提供执行细节和接地信息。
  - **工具制作LLM**：基于SOP节点文本、决策树位置、以及数据收集轨迹，生成候选工具。
  - **测试-修复循环**：候选工具在完整训练集上测试，失败案例由反射LLM诊断，然后工具制作LLM重写。预算3轮，选择通过率最高的部署。
  - **智能体微调**：将强教师模型（GLM-4.7）的轨迹蒸馏到小型学生模型（Qwen3 32B / GLM-4.5-Air），使用LoRA。混合轨迹：75%有工具但随机禁用25%，25%全无工具，以保证回退鲁棒性。
  - **运行时架构**：智能体可调用工具（通过子智能体或主智能体直接调用），失败时回退到代码生成。
- **数学/算法**：无显式公式，流程为：数据收集 → 工具生成 → 测试 → 反射诊断 → 重写（最多3轮）。工具函数签名：`(warehouse, timestamp, context) → (verdict, observed_value, threshold, explanation)`。

## 6. 论文的主要结论与发现

- **主要结论**：
  - 工具调用相比基线代码生成，p50延迟降低42%，端到端错误率降低高达53%（Qwen3 32B上36%，GLM-4.5-Air上53%）。
  - 直接调用工具（主智能体调用）比子智能体调用进一步降低62% p50延迟（在控制模型不变情况下）。
  - 工具制作流水线中，数据收集轨迹和修复循环两者均不可或缺：移除某一组件，pass@1下降5-10个百分点。
  - 瓶颈出在SOP规范质量：剩余错误集中在4个规范不明确或边缘案例未覆盖的节点，通过规范澄清和数据增强，pass@1可从94.5%提升至99.9%。
  - 版本化工具日志暴露了三个上游数据不一致问题（字段类型差异、语义不匹配、格式变化），而这些在运行时变化代码中隐藏。
- **其他发现**：
  - 工具可跨模型使用（GLM-4.7生成的工具服务Qwen3和GLM-4.5）。
  - 标签少量案例即可达接近全数据性能（N=5时91.8% vs 94.5%）。
  - 无标签版本（投票+LLM法官）可达91.6% pass@1，接近有标签上限。

## 7. 优点

- **方法创新**：将SOP编译为环境接地、经验证的版本化工具，结合制作和修复循环，超越单纯工具合成或提示工程。
- **实用性强**：在真实生产系统中部署，并展示了显著的延迟降低和错误率降低，有实际工业价值。
- **组件间因果分析透彻**：通过系统的消融实验（数据轨迹、修复循环、修复策略、内容成分）揭示了每个组件的贡献和相互作用。
- **审计和运维友好**：工具版本化与日志记录帮助发现数据漂移、环境不一致，并支持安全回滚和配置化部署。
- **鲁棒性设计**：智能体通过混合轨迹微调，可在工具缺失时自动回退到代码生成，没有显著性能下降。
- **数据效率**：少量标注案例即可达到良好性能，降低实际部署成本。

## 8. 不足与局限

- **应用领域局限**：仅验证了仓库出库码头一个场景，虽具有代表性但单一。对于自由形式的运行手册、多步推理、非结构化任务等，泛化性未建立。
- **依赖标注数据**：工具制作需要每个节点的标注案例（虽然无标签版本接近，但有差距）。完全自动化仍有距离。
- **规范缺陷需人工介入**：澄清SOP中的歧义和边缘案例本质上是人力任务，工具制作无法自动修复底层规范。
- **资源成本**：工具制作虽是一次性但需强模型（如GLM-4.7或Opus）和多次迭代，算力消耗较高；小模型（Qwen3 235B、Flash）效果差，甚至出现反向收益。
- **完全自动化有风险**：修复循环仍保留人类监督（评审通过后才部署），无法保证所有失败被自动捕获。论文也承认“cannot yet guarantee that every failure would be caught without human review”。
- **实验覆盖有限**：缺乏对其他类型SOP（如多模态、因果推理）的评估，也未讨论工具在更复杂决策树或动态环境中的表现。
- **可能存在的偏差**：采用教师轨迹过滤后剩余92%的通过率，可能引入蒸馏偏差；生产环境中的阴影测试、人工评审等可能隐含选择偏差。
