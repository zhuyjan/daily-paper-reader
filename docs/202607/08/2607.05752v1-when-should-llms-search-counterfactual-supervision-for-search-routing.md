## 摘要
搜索增强的语言模型可以利用外部证据来弥补参数化知识的局限性，但搜索并非总是有益的：模型可能对自己已经能回答的问题发起搜索，或者在更合适进行纠正、澄清或弃权时，依赖有噪声的证据。我们将此问题形式化为实例级搜索路由问题：即相对于不执行搜索的执行，决定是否需要搜索以提高任务成功率。为获取监督信号，我们比较同一问题下不搜索和强制搜索的结果，并根据任务特定的成功与否构建一个包含“不搜索”、“搜索”和“未解决”的 oracle。利用该 oracle 作为评估准则和学习信号，我们通过监督微调和偏好优化训练搜索路由策略，将 Gemma E2B 在 oracle 符合条件的示例上的路由宏F1从0.7082提升至0.8235，Qwen3.5-4B从0.7053提升至0.8365。进一步分析表明，学习到的策略减少了模型特定的路由失败：Gemma 主要学会了不搜索的约束，而 Qwen 进一步减少了遗漏搜索；剩余的“未解决”案例揭示了涉及模型容量、检索预算、证据使用和策略行为的异质性瓶颈。

## Abstract
Search-augmented language models can use external evidence to compensate for limitations in parametric knowledge, but search is not uniformly beneficial: models may call search for questions they can already answer, or rely on noisy evidence when correction, clarification, or abstention would be more appropriate. We formulate this as an instance-level search-routing problem: deciding whether search is needed to improve task success relative to a no-search execution. To derive supervision, we compare no-search and forced-search outcomes for the same question and construct an oracle over NO SEARCH, SEARCH, and UNSOLVED based on task-specific success. Using this oracle as both an evaluation criterion and a learning signal, we train search-routing policies with supervised fine-tuning and preference optimization, improving routing macro-F1 on oracle-eligible examples from 0.7082 to 0.8235 for Gemma E2B and from 0.7053 to 0.8365 for Qwen3.5-4B. Further analysis shows that the learned policies reduce model-specific routing failures: Gemma primarily learns no-search restraint, while Qwen further reduces missed search; residual UNSOLVED cases reveal heterogeneous bottlenecks involving model capacity, retrieval budget, evidence use, and policy behavior.

### 2. 论文提出的方法论
- **核心思想**：通过比较同一问题在“无搜索”和“强制搜索”两种控制条件下的任务成功结果，构建一个基于成功率的 **oracle**，将每个实例标注为 NO SEARCH、SEARCH 或 UNSOLVED，并仅用前两类标签进行监督学习。
- **关键技术细节**：
  1. **数据收集**：对每个问题收集三条轨迹：无搜索轨迹 N(q)、强制搜索轨迹 S(q)、自由策略轨迹 P(q)（基模型在选择性搜索提示下的行为）。
  2. **Oracle 构建**：评估两条控制轨迹的最终响应是否成功（PopQA 用别名感知事实性判断，KUQ 用分辨率导向判断），定义：
     - NO SEARCH：无搜索成功
     - SEARCH：无搜索失败但强制搜索成功
     - UNSOLVED：两者均失败（排除于路由训练和评估）
  3. **训练**：
     - **SFT**：对 NO SEARCH 实例，目标为成功的无搜索响应；对 SEARCH 实例，目标仅为首次搜索调用动作（而非完整后续轨迹）。
     - **偏好优化（DPO）**：使用 oracle 一致的首动作为 chosen，相反动作为 rejected（优先从实际自由策略错误中选取）；损失函数为 `L = L_DPO + α * L_NLL(chosen)`，加入 chosen 响应的负对数似然正则化。
  4. **评估指标**：在 oracle 符合条件的示例上计算路由准确率、宏F1、条件过度搜索率（NO SEARCH 上的假阳性率）和条件不足搜索率（SEARCH 上的假阴性率）。

- UNSOLVED 案例包含异质性瓶颈：部分仅能由更大模型、扩大检索预算或后训练策略单独恢复，说明失败原因多元，不宜归入简单路由标签。

### 7. 优点
- **反事实 oracle 设计**：基于实际任务成功结果而非人工判断，避免主观性，且可适应不同模型能力。
- **解耦第一动作**：训练专注于搜索决策，不强制优化后续搜索流程，使监督信号更聚焦。
- **保留 UNSOLVED 作为诊断**：不强制二分类，避免将混合失败转化为噪声标签，为后续改进提供方向。
- **联合纠正双向错误**：通过 SFT + 偏好优化同时减少过度搜索和不足搜索，符合实例级需求。
- **模型特定 oracle**：由于 oracle 依赖于当前模型的表现，训练信号自然适配不同模型的参数知识和搜索能力。

### 8. 不足与局限
- **oracle 的依赖**：标签依赖于当前模型、工具、搜索预算和评判器配置，不具有绝对普适性；更换设置后标签可能变化。
- **仅关注第一动作**：未优化搜索后的查询细化、多跳检索、证据选择或答案合成，实际系统后续步骤仍有重要影响。
- **诊断干预非因果独立**：如“更大模型强制搜索”同时改变模型容量、查询和合成，无法精确归因。
- **实验范围有限**：仅测试两个模型（Gemma E2B、Qwen3.5-4B）和两个数据集（PopQA、KUQ），泛化性待研究更多模型和场景。
- **未评估实际成本**：未讨论搜索调用带来的延迟和计算开销，或在不必要搜索时浪费的资源量化。
- **未进行人类评估**：任务成功由自动评判器决定，可能引入与人类判断的偏差。
