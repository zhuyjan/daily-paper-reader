## 摘要
大型语言模型（LLM）智能体需要能够从环境反馈中改进长期决策的后训练方法。然而，现有的智能体后训练流程通常将数据策展视为固定的预处理步骤，主要关注数据增强，而忽略了过滤、精炼以及对下游失败的适应。我们提出CurateEvo，一种面向智能体后训练数据策展的失败驱动动态演化框架。CurateEvo将策展策略表示为可执行代码，并使用来自保留开发集的失败轨迹迭代重写该代码。在每个epoch，演化后的策略将固定原始语料转换为监督微调数据、强化学习数据和推理时记忆库。演化过程首先通过诊断重复失败模式并相应增强、过滤或精炼数据来提高有效性，然后通过成本感知目标修剪冗余或低效用训练轮次来提高效率。在ACEBench-Agent、BFCL-V4和τ²-Bench上，在标注和野数据设置下的实验表明，CurateEvo始终优于先前的策展方法，平均得分分别提高3.2和2.7分。进一步分析表明，CurateEvo与不同的后训练配方兼容，并大幅降低策展开销。

## Abstract
Large language model (LLM) agents require post-training methods that can improve long-horizon decision making from environment feedback. However, existing agentic post-training pipelines often treat data curation as a fixed preprocessing step, focusing mainly on data augmentation while neglecting filtering, refinement, and adaptation to downstream failures. We propose CurateEvo, a failure-driven dynamic evolution framework for agentic post-training data curation. CurateEvo represents the curation strategy as executable code and iteratively rewrites it using failed trajectories from a held-out development set. At each epoch, the evolved strategy transforms a fixed raw corpus into supervised fine-tuning data, reinforcement learning data, and an inference-time memory bank. The evolution process first improves effectiveness by diagnosing recurring failure modes and augmenting, filtering, or refining data accordingly, and then improves efficiency by pruning redundant or low-utility training turns under a cost-aware objective. Experiments on ACEBench-Agent, BFCL-V4, and τ^2-Bench under both labeled and wild-data settings show that CurateEvo consistently outperforms prior curation methods, improving average scores by 3.2 and 2.7 points, respectively. Further analyses demonstrate that CurateEvo is compatible with different post-training recipes and substantially reduces curation overhead.

## 2. 论文提出的方法论：核心思想、关键技术细节、公式或算法流程

### 2.1 核心思想

- **将数据策展策略表示为可执行代码**，并通过一个LLM驱动的代码进化智能体（code-evolution agent）基于开发集上的失败轨迹迭代重写该代码。
- 在每个进化轮次，当前策展策略将固定的原始语料（raw corpus）转换为三类资源：
  - 监督微调数据（SFT data）
  - 强化学习数据（RL data）
  - 推理时记忆库（inference-time memory bank）
- 进化过程分为两步：
  1. **有效性优化**：诊断重复失败模式，通过数据增强、过滤、精炼来弥补能力缺口。
  2. **效率优化**：在成本感知的目标下修剪冗余、低效用或过长的训练轮次，减少训练规模。

### 2.2 关键技术细节

- **问题形式化**：
  - 策展策略 ρ 将原始语料 D_raw 映射为：ρ : D_raw → (D_sft^ρ, D_rl^ρ, M_mem^ρ)。
  - 后训练从固定基模型 π_base 出发，使用固定训练配方（SFT+GRPO）训练策略 π_ρ。
  - 推理时，策略可额外检索记忆库 M_mem^ρ。
  - 优化目标：最大化在开发集上的性能，同时控制训练成本。

- **进化流程**（每个epoch e）：
  1. 执行 ρ_e 得到 D_sft^e, D_rl^e, M_mem^e。
  2. 从基模型重新开始训练得到 π_e，并在开发集上评估，收集失败轨迹 T^-_e、性能 s_e 和策展档案 Σ_e。
  3. LLM进化智能体接收 (ρ_e, T^-_e, s_e, Σ_e) 并重写代码得到 ρ_{e+1}。
  4. 优化目标 J(ρ) = P(ρ) - λC(ρ)，其中 P(ρ) 是下游有效性的代理（由当前失败模式指导），C(ρ) 是标准化训练轮次成本（使用 tanh 归一化）。
  5. 若新策略未改善目标，则回滚以防错误级联。

- **有效性优化**：进化智能体首先从失败轨迹中诊断出失败模式（如错误工具选择、参数绑定错误、长程规划弱、恢复能力差等），然后修改策展代码以生成、过滤或精炼针对这些失败模式的数据。
- **效率优化**：通过去重、剪枝低质量样本、压缩重复交互模式、截断过长轨迹来减少训练规模，同时保留覆盖稀有失败模式的关键样本。

## 6. 论文的主要结论与发现

1. **CurateEvo 在所有 benchmark 上均优于先前方法**，在标注数据上平均提升 3.2 分，在野数据上提升 2.7 分。
2. **有效性优化和效率优化均贡献显著**：去除有效性优化导致平均下降约 7 分；去除效率优化也有小但一致的下降。
3. **SFT、RL 和记忆三种资源互补**：移除任意一种都会导致性能下降，尤其野数据下下降更明显（强调过滤和精炼的重要性）。
4. **CurateEvo 兼容不同的后训练配方**：与 AgentGym-RL、ProRL-Agent 结合后平均额外提升 21.3 分，说明其作为数据侧模块的泛用性。
5. **策展开销大幅降低**：每保留1K轮次的 token 和耗时约为对比方法的一半，验证了成本感知修剪的有效性。
6. **演化在约 3 epoch 后性能饱和**，后续轮次主要减少训练规模而不显著提升性能，验证了首先提升有效性、再提升效率的设计。
7. **成本权重 λ 的最优值为 0.3**，过大或过小均导致性能下降，表明有效性与效率应联合优化。
