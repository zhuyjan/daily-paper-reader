## 摘要
训练多模态搜索代理进行多跳推理仍然具有挑战性，原因在于存在根本性的结构脱节：现有流程独立构建训练数据、搜索环境和奖励信号，导致合成结构元数据被丢弃、环境依赖不可复现的外部引擎、以及强化学习奖励在轨迹层面上仍然稀疏。我们提出**SearchEyes**，它使用类型化知识图谱作为**模拟搜索世界**的骨干，统一了这三个组件。我们提出**感知-知识链（PKC）**，用于在Wikidata5M的视觉-知识交集上采样受限的多跳路径，保留跳级实体元数据，同时定义自包含的搜索世界和逐级奖励锚点。我们进一步提出**跳锚策略优化（HaPO）**，它重用这些锚点进行逐级信用分配，无需单独训练的过程奖励模型。在六个多模态知识密集型基准上的实验表明，SearchEyes在开源多模态搜索代理中实现了最先进的性能，其中SearchEyes-27B相比最强开源基线平均提升了6.2个百分点。

## Abstract
Training multimodal search agents to perform multi-hop reasoning remains challenging due to a fundamental structural disconnect: existing pipelines construct training data, search environments, and reward signals independently, causing synthesized structural metadata to be discarded, environments to rely on irreproducible external engines, and RL rewards to remain sparse at the trajectory level. We present \textbf{SearchEyes}, which uses a typed knowledge graph as the backbone of a \emph{simulated search world} that unifies all three components. We propose \textbf{Perception-Knowledge Chains (PKC)} to sample constrained multi-hop paths over the visual-knowledge intersection of Wikidata5M, retaining hop-level entity metadata that simultaneously defines a self-contained search world and step-level reward anchors. We further propose \textbf{Hop-Anchored Policy Optimization (HaPO)}, which reuses these anchors for step-level credit assignment without a separately trained process reward model. Experiments on six multimodal knowledge-intensive benchmarks show that SearchEyes achieves state-of-the-art performance among open-source multimodal search agents, with SearchEyes-27B improving over the strongest open-source baseline by 6.2 points on average.%

当前多模态搜索代理的训练面临一个根本性结构脱节：**训练数据、搜索环境和奖励信号被独立构建**。

- **数据端**：之前的方法虽然利用图结构合成多跳问题，但合成后丢弃所有中间元数据（路径结构、实体 ID、关系类型），只保留问答对。
- **环境端**：由于没有共享的结构信息，现有系统只能依赖外部搜索引擎（如 Web API）作为训练环境，导致**不可复现、非确定性、高 API 成本**。
- **奖励端**：强化学习奖励只能在轨迹末端基于最终答案计算，对于长链多跳推理，正确完成整条链的概率随跳数急剧下降，使得轨迹级奖励极度稀疏，难以进行有效的策略优化。

**整体含义**：该论文旨在通过一个**类型知识图谱**作为统一主干，构造一个**模拟搜索世界**，同时驱动数据合成、环境模拟和 RL 训练，从而消除这一结构断裂，实现可复现、细粒度奖励的多模态搜索智能训练。

## 2. 方法论

### 2.1 核心思想

利用 Wikidata5M、Wiki6M（OVEN）和 Wikipedia 图像构建**类型知识图谱** G = (V, R, T, φ)，其中实体具有结构化三元组、文本描述和图像（部分实体为视觉实体）。该图谱直接作为**自包含的搜索环境**（文档集合 D 对应每个实体的维基百科摘要），提供确定性检索（BM25 + 稠密检索的 RRF 融合）。所有实体通过 Wikidata QID 唯一关联，从而保留路径元数据。

### 2.2 关键技术细节

#### (1) Perception-Knowledge Chain (PKC) 数据合成

- **约束路径采样**：在知识图谱上执行受限随机游走，生成多跳路径 p = (v1 → v2 → ... → vK+1)，施加以下约束：
  - **C1: P–K 交替**：起始跳为感知跳（P，目标为视觉实体），后续与知识跳（K）严格交替；至少两个 P 跳确保多次视觉感知。
  - **C2: 消歧约束**：至少一跳使用一对多谓词，并添加约束边，使推理图的树宽 ≥2，迫使代理必须验证约束条件。
  - **C3: 语义域多样性**：路径覆盖至少 3 个语义域（Person/Work/Org/Geo），且相邻谓词域不同。
  - **C4: 抗捷径过滤**：排除高中心性实体、元谓词（如 instance_of）、重复路径。
- **信息隐藏问题生成**：用 LLM 将路径转换为自然语言问题，隐藏：锚点实体的名称（仅靠图像）、关系序列（仅给一个域提示）、消歧实体名称（使用描述性短语）。确保问题不泄露任何路径实体名。
- **轨迹合成（SFT 数据）**：在改进的环境中生成轨迹——改进环境对黄金实体检索分数进行增强（β=3），并使用 LLM 对观察结果去噪。通过拒绝采样得到正确轨迹（~42% 成功率），导出时还原为原始观测，供学生策略在带掩码的监督微调（SFT）中使用。

#### (3) Hop-Anchored Policy Optimization (HaPO)

- **基础**：基于 GRPO，但引入步骤级信用分配。
- **跳锚点优势**：定义语义锚点：若轨迹在某个步骤检索到黄金实体 vk，则将其视为跳锚点。在同一跳锚点组内计算组相对优势 Â̂(i,t)hop，然后传播到该步骤之后的所有 token。
- **组合优势**：α·Â̂ep + (1-α)·Â̂hop，α=0.3 为最佳。
- **致命感知掩码**：若连续 M≥3 个工具调用错误，则后续 token 优势置 0；对有效前缀采用单侧钳位（仅保留正优势）。
- **光滑非对称门控**：用 sigmoid 函数替代硬截断，对负优势使用更大的温度 γ⁻=1.05 以更强调抑制。

## 7. 优点

- **统一框架消除结构脱节**：利用类型知识图谱同时作为数据源、搜索环境、奖励锚点的基石，首次实现数据–环境–算法的协同设计。
- **自包含搜索环境**：基于维基百科构建的确定性检索系统保证完全可复现、低成本，避免外部 API 不可控问题。
- **细粒度步骤级奖励**：HaPO 无需单独训练过程奖励模型，通过复用合成路径中的黄金实体序列实现步骤级信用分配，有效缓解长链奖励稀疏。
- **高质量数据合成**：PKC 设计多个结构化约束（P–K 交替、消歧、域多样性、抗捷径），使合成问题真正需要多跳推理，而非表面模式。
- **开源贡献**：承诺公开所有数据、代码和模型权重，促进后续研究。
- **参数效率**：9B 模型性能接近 30B+ 开源模型，降低部署门槛。

## 8. 不足与局限
