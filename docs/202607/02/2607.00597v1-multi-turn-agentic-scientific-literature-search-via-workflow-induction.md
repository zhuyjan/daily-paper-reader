## 摘要
科学文献搜索往往需要超越单次查询的论文检索：用户的意图不明确、依赖偏好且会随着交互而演变。现有的搜索代理通常依赖于固定的流水线或隐式的纯语言推理，导致其搜索策略难以控制、检查和优化。我们提出PaperPilot，一种将科学搜索视为工作流归纳的多轮文献搜索代理。给定一篇锚点论文和用户查询，PaperPilot构建一个由论文搜索算子（包括关键词搜索、引文扩展、过滤、评分、重排序和证据提取）组成的可执行有向无环图。随后使用用户反馈来优化查询和工作流本身。我们通过监督工作流模仿和对受控工作流损坏的偏好优化来训练PaperPilot。实验表明，在多轮交互下，PaperPilot-9B相比基础Qwen3.5-9B工具集代理，Hit@5从58.0提升至77.0，MRR从47.5提升至59.4，nDCG@10从26.8提升至32.5，同时工作流执行错误从9.5%降至0%。这些结果表明，显式、可编辑的搜索工作流为将文献搜索代理与复杂科学意图对齐提供了有效且可控的接口。

## Abstract
Scientific literature search often requires more than retrieving papers from a single query: users' intents are underspecified, preference-dependent, and evolve through interaction. Existing search agents typically rely on fixed pipelines or implicit language-only reasoning, making their search strategies difficult to control, inspect, and refine. We introduce PaperPilot, a multi-turn literature search agent that frames scientific search as workflow induction. Given an anchor paper and a user query, PaperPilot constructs an executable DAG of paper-search operators, including keyword search, citation expansion, filtering, scoring, reranking, and evidence extraction. User feedback is then used to refine both the query and the workflow itself. We train PaperPilot with supervised workflow imitation and preference optimization over controlled workflow corruptions. Experiments show that PaperPilot-9B improves over the base Qwen3.5-9B toolset agent under multi-turn interaction, increasing Hit@5 from 58.0 to 77.0, MRR from 47.5 to 59.4, and nDCG@10 from 26.8 to 32.5, while reducing workflow execution errors from 9.5% to 0%. These results show that explicit, editable search workflows provide an effective and controllable interface for aligning literature search agents with complex scientific intent.

### 2. 论文提出的方法论：核心思想、关键技术细节

*   **核心思想：工作流归纳**。PaperPilot将科学文献搜索从一次性的查询-结果匹配，转化为一个**逐步构建和优化可执行工作流**的过程。该工作流是一个有向无环图（DAG），图中的每个节点代表一个具体的搜索操作（算子），边代表数据（如论文集合、关键词等）的流动。
*   **关键技术细节**:
    1.  **操作符库 (PaperPilot-Toolset)**：预定义了一组类型化的论文搜索算子，包括：
        *   信息源（Sourcing）：关键词搜索、引文扩展（向前/向后）、网络解析。
        *   处理（Combine/Filter）：并集、去重、按条件过滤。
        *   排序（Scoring）：基于特征的评分。
        *   重排序（Rerank）：LLM重排序、NLI过滤。
        *   输出（Output）：证据提取、关系图构建。
    2.  **工作流表示**：工作流被定义为 `G = (V, E)`，节点 `v_i` 是具有特定参数的操作符实例，边 `(v_i, v_j)` 表示类型一致的数据流。最终节点输出一个排名列表、证据列表或结构图。
    3.  **交互驱动的工作流优化**：在多轮对话中，用户提供反馈（如“范围太宽”、“关注近期工作”）。代理不是简单地将反馈加入查询文本，而是将其解析为对工作流的具体编辑指令，例如：
        *   `添加`一个“年份 >= 2020”的过滤节点。
        *   `修改` 一个评分的权重。
        *   `删除`一个不相关的关键词搜索节点。
    4.  **两阶段训练方法**：
        *   **阶段一：监督工作流模仿**。使用一个强大的教师模型（如GPT-5.4）生成高质量的工作流轨迹（仅保留成功案例），然后对目标模型（Qwen3.5-9B base）进行监督微调（SFT）。
        *   **阶段二：偏好优化**。通过故意“破坏”成功的工作流（如添加无效引用、遗漏关键节点）来构建“好-坏”工作流对，然后使用DPO（直接偏好优化）及其变体（IPO）来训练模型，使其学会偏好更优、更鲁棒的工作流。

### 6. 论文的主要结论与发现

1.  **自适应工作流优于固定流程**：使用PaperPilot-Toolset的自适应工作流在单轮搜索中显著优于固定Workflow（例如，GPT-5.4的Hit@5从52.0提升到79.5），证明了根据查询意图定制搜索策略的有效性。
2.  **多轮交互在可控下有效**：多轮交互能进一步提升性能，但前提是用户反馈能被有效转化为工作流编辑。对于未经训练的模型（如Qwen3.5-9B），多轮交互反而因工作流编辑错误增加而导致性能下降。

4.  **性价比突出**：PaperPilot-9B的成本效益（每美元成功检索案例数）非常出色，尽管是9B的小模型，但在Hit@5等指标上甚至超越了单轮交互的GPT-5.4 Web Search，且远优于昂贵的DeepResearch。
5.  **显式工作流是有效接口**：人体实验验证了这一点，用户在PaperPilot上的满意度（74.7%）远高于GPT-5.4（32.0%）和DeepResearch（8.0%），表明可编辑的显式工作流让用户感觉更满意、更能控制搜索过程。

### 7. 优点

*   **系统性创新**：将文献搜索问题形式化为“工作流归纳”，为交互式搜索提供了一个优雅且强大的理论框架。
*   **强解释性与可控性**：显式的DAG工作流使得搜索策略完全透明，用户可以直接检查和修改搜索逻辑，这比依赖LLM内部推理的黑箱系统要进步得多。
*   **鲁棒的训练策略**：通过“监督模仿”+“偏好优化”（尤其是通过工作流损坏构建偏好数据）的方法，有效地教会了模型生成和编辑高质量、结构化的工作流，解决了许多代理系统在长期交互中不稳定、易犯错的核心问题。
*   **全面的实验设计**：不仅评估了主任务效果，还深入分析了工作流质量、编辑稳定性和成本效益，并通过人体实验验证了真实用户体验，论证充分。
*   **实用性**：在9B参数的小模型上取得了与大型商业模型相当甚至更好的结果，显示了低成本、高效率的实际应用潜力。

### 8. 不足与局限

*   **依赖预定义工具库**：PaperPilot的性能受限于预定义的符号操作符库。对于某些非常专业或新颖的搜索行为，该库可能无法覆盖，限制了其在特定领域的泛化性。
*   **训练数据偏差**：工作流的监督数据是从教师模型（可能是GPT-5.4）生成的。这意味着PaperPilot-9B可能会继承教师的“盲点”或偏好，例如倾向于使用某种特定的搜索策略。
*   **基准测试的局限性**：基准测试主要聚焦于计算机科学领域，并且使用受控的隐藏黄金论文集进行评估。这可能无法完全反映在真实、开放的科学文献搜索场景中的表现。
*   **模拟器的局限性**：虽然使用LLM用户模拟器保证了可重复性，但模拟的反馈与真实人类用户的反馈仍有差距。未来的工作需要在真实用户场景下进行评估。
*   **算力信息不明确**：论文未提供训练所需的精确GPU资源（型号、数量、时间），这对于评估方法的可复现性和资源成本是一个小遗憾。
