## 摘要
自主智能体越来越需要能通过反馈改进可执行策略，但现有评估往往将该过程简化为最终得分，或将其与开放式软件工程进展混为一谈。我们提出自主策略演化，这是一种受控的评估设置，其中主模型智能体在固定的交互预算下反复编辑可执行策略系统。我们在EvoPolicyGym中实例化该设置，这是一个基于紧凑型交互式强化学习环境构建的基准，用于评估智能体如何迭代改进探索的策略。在EvoPolicyGym套件上，GPT-5.5在所有16个环境中取得了最强的综合排名得分和前两名表现。除了排行榜结果，EvoPolicyGym还提供了轨迹级诊断，可区分智能体如何分配预算、将反馈转化为参数调优。这些分析表明，强大的自主策略演化不仅取决于孤立的任务胜利，还取决于在有限反馈下发现任务适当的机制并改进策略。

## Abstract
Autonomous agents are increasingly expected to improve executable policies through feedback, yet existing evaluations often collapse this process into a final score or confound it with open-ended software-engineering progress. We introduce Autonomous Policy Evolution, a controlled evaluation setting in which a harness-model agent repeatedly edits an executable policy system under a fixed interaction budget. We instantiate this setting in EvoPolicyGym, a benchmark built from compact interactive RL environments that evaluates how agents iteratively improve explored policies. On the EvoPolicyGym suite, GPT-5.5 achieves the strongest aggregate rank score and top-two performance on all 16 environments. Beyond leaderboard results, EvoPolicyGym also provides trajectory-level diagnostics that distinguish how agents allocate budget, convert feedback into parametric tuning. These analyses show that strong autonomous policy evolution depends not only on isolated task wins, but on discovering task-appropriate mechanisms and refining policies under bounded feedback.

- **现有评估的缺陷**：当前的自主智能体评估要么将策略改进过程坍缩为一个最终分数（如最终回报），要么与开放式的软件工程进展混为一谈（如 SWE-bench）。这些方法无法区分“盲目重试”、“过拟合可见反馈”、“脆弱的特例处理”等轨迹级失败模式，也缺乏对固定预算下策略演化过程的控制性评测。
- **核心问题**：如何在一个受控的、可重复的设置中，独立地衡量智能体将有限的环境反馈转化为可泛化策略改进的能力？这要求评估不仅关注最终结果，还要捕捉迭代过程中的决策（如何分配预算、何时探索/利用、如何从稀疏证据中提炼改进）。
- **研究意义**：通过形式化“自主策略演化”这一概念，并构建对应的基准 EvoPolicyGym，为研究自演化智能体与有限预算、轨迹级反馈之间的交互提供了标准化、可诊断的测试平台。

## 2. 方法论：核心思想、关键技术细节、算法流程（文字说明）

### 2.1 核心思想
- **自主策略演化**：一个编码智能体在一个固定的交互预算（episode budget）下，反复编辑一个可执行策略系统（policy system，包含 policy.py、辅助模块、参数等），仅通过服务器返回的训练反馈（轨迹摘要、回报等）来驱动改进，最终由服务器在隐藏的验证集上选择最佳检查点，并在隐藏的留出集上评估其泛化性能。
- **关键设计**：
  - **可见性边界**：训练反馈对智能体可见；验证和留出评估对智能体隐藏，防止过拟合。
  - **固定预算**：每个环境 128 个 episode 的交互预算，智能体自行决定每次提交花费多少 episode。
  - **轨迹级反馈**：每次提交后返回详细结果（回报、轨迹、错误等），支持细粒度诊断。

### 2.2 技术细节
- **环境、策略、情节的定义**：
  - 环境：具有 `reset/step` 接口的交互任务（Gymnasium 风格）。
  - 策略：一个可执行的 Python 类，包含 `reset(episode_index)` 和 `act(obs)`，内部可含状态、模块、参数等。
  - 情节（Episode）：一次完整的策略-环境交互，累积回报为评价指标。
- **协议**：智能体观察当前工作空间（Wi）、历史反馈（Fi）和剩余预算（Bi），然后生成补丁（patch）并决定是否提交。提交后服务器快照策略，执行请求的 episode，返回反馈（∆Fi）并扣除预算。预算耗尽后，服务器自动进行隐藏验证选点与留出评估。
- **评分规则**：
  - 每个环境内，按隐藏留出均值回报排序，计算排名分数：`s_{m,e} = 1 - (rank_e(m) - 1)/(N_e - 1)`。

- **诊断分析**：
  - **结构合成 vs. 参数调优**：结构合成编辑引入新的 AST 拓扑（去除数值常量后），参数调优编辑在保持拓扑下修改常量。通过统计哪种编辑更能提升验证得分来分析。
  - **轨迹相线**：绘制预算消耗轴上最佳验证得分的变化，标记结构/参数编辑阶段、回滚、重测等事件。
  - **反馈利用追踪**：对典型环境（如 CarRacing）逐条分析证据→归因→策略修订→结果，展示高质量智能体如何从反馈中提取信息并转化为机制级代码变化。

## 6. 主要结论与发现

1. **GPT-5.5 领先**：GPT-5.5 获得最高 Core16 排名分数（0.891），在全部 16 个环境中均位列前两名，9 次获得第一名。它是唯一在所有环境保持顶级表现的智能体。
2. **任务特异分化**：Claude Opus 4.7 在 MiniGrid 家族上表现出色（0.938），但在调参任务（如 BipedalWalker）上较弱（仅 0.24 相对得分）。不同模型在不同任务家族上有偏好。
3. **结构合成是关键瓶颈**：在需要合成新机制的任务（如像素感知、符号规划）上，高性能智能体（GPT-5.5、Claude Opus 4.7）的结构编辑成功率高达 41%~48%，而弱智能体（MiniMax-M3、DeepSeek-V4-Pro）的结构编辑成功率仅 3%~10%。这表明弱智能体的主要失败模式是未能发现正确的控制结构。
4. **参数调优依赖于已有结构**：在调参主导的任务上，一旦获得合理的控制器结构，各智能体的表现差距缩小（0.67~0.99），但弱智能体往往连一个可行的结构都无法达到。
5. **轨迹级诊断揭示策略演化效率**：通过事后最佳得分演化曲线，可以看出高智能体往往在早期就发现高质量候选策略（如 CarRacing 中 GPT-5.5 在第 30 个 episode 前即达到最佳），而弱智能体则大量消耗预算于无效结构探索。

## 8. 不足与局限

- **预算设置单一**：仅采用 128 episode 一个预算水平，未探索预算大小对策略演化行为的影响。
- **单次运行**：每个条件只运行一次，缺乏统计显著性检验。
- **缺少 RL 基线**：无法与基于梯度的强化学习方法进行直接对比，限制了结论的普适性。
- **工具耦合**：模型与工具强绑定，无法区分是模型本身能力还是工具接口差异导致性能差距。
- **诊断工具的限制**：AST 拓扑变化仅为保守代理，可能漏掉语义等价但结构不同的演化；合成/调优的分类是分析透镜，并非任务客观属性。
- **环境覆盖有限**：虽然 16 个环境多样，但仍未包括真实世界的长期交互任务（如网页导航、机器人部署等）。
- **性能指标单一**：仅使用回报这一标量指标，未考虑安全性、稳定性、样本效率等其他维度。
- **无开放结束任务**：专注于“策略演化”而非“技能发现”或“开放式探索”，可能忽略长期创造能力。
