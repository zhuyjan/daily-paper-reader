## 摘要
AI智能体正从答案引擎演变为持续运行的团队，它们使用工具、委派工作、从经验中学习，并修改塑造其未来行为的人工制品。部署时的关键问题不再仅仅是智能体能做什么，而是谁控制着它们被允许成为什么。我们提出logos，一个用于自我进化与治理的可插拔层，它增强而非取代现有的多智能体框架。logos将异构多模态输入（包括文档、图像、音频、表格、数据库、API和人类指令）编译为版本化的智能体包，其中包含智能体、工具、知识、测试、权限和策略。在运行期间，它将智能体活动转化为可移植、可审计的事件轨迹，并在框架和后端之间应用失败关闭验证。每个学习到的提示、记忆、技能、工具、角色或工作流程，在持有执行证据、受人类控制的策略和明确授权允许其晋升之前，始终是未经验证的候选版本。这种架构实现了“可验证的人-智能体循环工程”：智能体可以行动、提问、学习并提出改进建议，而人类可以在不中断持续操作的情况下引导目标、权限、审批和不可逆操作。logos为可问责的自动化提供了动态逻辑。智能体可以以机器速度进化，但只有证据和人类权威才能闭合该循环。

## Abstract
AI agents are evolving from answer engines into persistent teams that use tools, delegate work, learn from experience, and modify the artifacts that shape their future behavior. The defining question for deployment is no longer merely what agents can do, but who controls what they are allowed to become. We introduce logos, a pluggable layer for self-evolution and governance that strengthens existing multiagent frameworks rather than replacing them. logos compiles heterogeneous multimodal inputs, including documents, images, audio, tables, databases, APIs, and human instructions into versioned agent packs containing agents, tools, knowledge, tests, permissions, and policies. During operation, it transforms agent activity into portable, auditable event traces and applies fail-closed verification across frameworks and backends. Every learned prompt, memory, skill, tool, role, or workflow remains an untrusted release candidate until held-out execution evidence, human-controlled policy, and explicit authorization permit its promotion. This architecture enables "verifiable human-agent loop engineering": agents can act, ask, learn, and propose improvements, while humans can steer objectives, permissions, approvals, and irreversible actions without interrupting continuous operation. logos provides a living logic for accountable automation. Agents may evolve at machine speed, but only evidence and human authority can close the loop.

1. **编译成功率**：Logos 编译器在生成内容上达到 C3/C4/C5 分别为 0.882 / 0.720 / 0.757，优于“一次性 LLM 构建”（0.631/0.286/0.334），接近手写模板代理的 0.923/0.808/0.829。并且 OpenAPI 工具摄入的探针通过率达 100%。
2. **端到端任务成功率**：编译帮助、但在某些套件上（如 gpt-4o-mini MATH-500）比直接单模型差，因此 Logos 使用验证–路由规则选择最佳求解器。
3. **门控自我进化**：在候选家族重放中，无门控采纳 60% 有害候选，代理信号门控采纳 40% 有害候选，而配对门控和任意时有效门控**未观察到任何有害采纳**，同时保留了所有有益家族。在完整提议选环中（非饱和套件），配对门控将版均回归数从 1.7 降至 0.7 以下。
4. **门控记忆**：当有显式训练信号时，门控记忆能提升 LongMemEval 4 个百分点，同时无门控记忆导致 LoCoMo 下降 3 个百分点；当无训练信号时，主动关闭记忆避免退化。
5. **路由与级联**：在执行验证的代码任务（HumanEval、MBPP）上，验证门控级联显著优于弱模型且不低于强参考模型；在非代码套件上改善不显著。自适应入口在困难维度上节省 20% 成本而不损失精度。
6. **安全委派**：Logos 在 400,000 个模拟任务中**未观察到任何未经授权的外部效应**，同时保持 94.0% 合规成功率（全自主仅 63.2%），并将人类干预从 100% 降至 39%。
7. **合约一致性**：Q9–Q22 的全部 14 项合约检查中，Logos 在关键指标（有害采纳、不安全操作、租户隔离、记忆过期使用、审计完整性等）上均达到理想值（0.000 或 1.000），远好于负控制策略。
8. **自助高级进化工具**（附录 F）：退休守卫将错误退休率从 96% 降至 0%；记忆编辑策略将检索效用提升约 33%；多样性搜索在欺骗性双盆地任务中达到 21/30 次成功（基线 8/30）；工具自我修复通过了所有 3 个有缺陷工具修复并阻止了 4 个敌对改写。

### 7. 优点

- **统一生命周期合约**：将构建、路由、验证、适应和人类监督整合为一个发布治理问题，而非零散机制。
- **分离证据与权限**：核心原则“提议不是晋升”被严格实现，候选必须经过根策略、留出执行证据和授权才能晋升，避免自我优化循环窃取控制权。
- **可插拔设计**：不替换现有多智能体框架，而是通过适配器增强，降低采用门槛。
- **细粒度门控**：提供固定配对门控（简单工程规则）和可选任意时有效门控（统计严格边界），适应不同风险需求。
- **人类–智能体循环可审计**：预算化问询、指令融合、根策略、证据支持推理、谱系记录使协作可追溯可控制。
- **实验设计严谨**：明确区分四类证据、声明每个实验的边界、使用多种随机种子和配对检验、公开默认超参数和协议细节。
- **广泛覆盖安全层面**：从工具安全、租户隔离、记忆污染、回滚审计到安全非回归轴，具有系统性的控制思考。

### 8. 不足与局限

- **计算资源不透明**：未报告使用的 GPU 型号、数量或训练成本，仅涉及 API 调用，缺乏可复现硬件信息。
- **实验生态偏合成**：大量实验基于生成模板、扰动和受控候选，而非真实用户行为或生产环境数据，因此结论（尤其是安全委派的零违规）仅限于生成的测试空间，不直接证明生产安全。
- **验证器假设过强**：多个机制（如级联非退化、门控记忆稳定屏幕）依赖于验证器的高覆盖率或低假正率，但论文承认“假接受仍为核心风险”；现实部署中验证器可能不完善。
- **任意时有效门控的假设限制**：需要条件超均匀性、可预测投注、流中 i.i.d. 留出等，且不能覆盖验证器错误、分布漂移或自适应过拟合。
- **迁移性仍需目标端重验证**：尽管设计了共享谱系库和目标端门控，但迁移增益可能为负，论文仅声明“迁移是一个提议机制，效用必须重新建立”。
- **实验对比公平性**：编译后系统可能使用额外 API 调用和验证器，而基准使用单次推理，因此在计算不对称性下比较时缺乏成本校准。论文也指出此点。
- **部分模块的统计保证弱**：如价值感知记忆的带刺更新是启发式信用分配，不是严格因果推断；安全委派中的人类问询策略基于启发式替代，而非精确 VOI 计算。
- **文档中符号体系复杂**：虽然提供了简洁的导论和符号表，但 58 页的长度和数百个数学符号可能对非专业读者构成理解障碍。
