## 摘要
长期记忆使LLM智能体能够充当持久助手，但用户事实会发生变化。一个有用的记忆系统必须知道当前真实的信息、过去真实的信息以及发生了什么变化。我们研究了"幽灵记忆"，这是一种状态协调故障，其中旧事实、当前事实和过渡事实在记忆库中共存，在检索时混合在一起，并误导答案模型。我们认为，记忆系统应从三个层面理解和优化：记忆库维护、检索和答案时间解析。我们提出了ATMA，一种针对现有记忆系统的状态感知覆盖层。ATMA在记忆库中保留被取代的记录和过渡记录，为查询请求的状态视图构建证据包，并向问答系统暴露当前、历史和过渡标签。我们进一步呼吁对记忆库、检索和答案层面的故障进行解耦评估，因为最终的问答准确率可能会隐藏幽灵记忆发生的位置。为了量化这种故障，我们构建了LTP（LoCoMo Temporal Plus），一个针对幽灵记忆的高冲突基准，并在LoCoMo上进行长对话泛化评估。在LTP上，Graphiti+ATMA相对于Graphiti将冲突准确率提升了0.240（绝对值）。在LoCoMo上，Graphiti+ATMA将时间F1从0.0295提升至0.1705。这些提升依赖于宿主，但表明明确的状态角色可以减少被最终问答准确率隐藏的记忆故障。

## Abstract
Long term memory lets LLM agents act as persistent assistants, but user facts change. A useful memory system must know what is true now, what used to be true, and what changed. We study \emph{ghost memory}, a state coordination failure in which old, current, and transition facts coexist in the memory bank, remain mixed during retrieval, and mislead the answer model. We argue that memory systems should be understood and optimized from three levels: bank maintenance, retrieval, and answer time resolution. We propose ATMA, a state aware overlay for existing memory systems. ATMA keeps superseded and transition records in the bank, builds evidence packets for the query's requested state view, and exposes current, historical, and transition labels to QA. We further call for decoupled evaluation of bank, retrieval, and answer level failures, since final QA accuracy can hide where ghost memory occurs. To make this failure measurable, we build LTP (LoCoMo Temporal Plus), a conflict heavy benchmark for ghost memory, and evaluate on LoCoMo for long conversation generalization. On LTP, Graphiti+ATMA improves conflict accuracy by 0.240 absolute over Graphiti. On LoCoMo, Graphiti+ATMA raises temporal F1 from 0.0295 to 0.1705. The gains are host dependent, but they indicate that explicit state roles can reduce memory failures hidden by final QA accuracy.

-   **研究动机与背景**：大型语言模型（LLM）智能体正从单轮对话转向提供持续的、长效的助手服务。这要求智能体拥有长期记忆，能够记住并更新用户的偏好、决策、过往对话等。然而，用户的事实性信息并非静态不变（如更换地址、修改计划等）。当记忆系统不加区分地存储所有信息，且无法正确识别和利用信息的“时效状态”（是当前有效、历史存档，还是变更过程）时，就会产生**“幽灵记忆”**——新旧信息混杂，在检索和回答时误导模型。
-   **论文的整体贡献**：论文提出，解决“幽灵记忆”不能简单地删除旧信息，而需要建立一个**状态感知**的记忆系统。关键在于将记忆的**存储（Bank）、检索（Retrieval）和回答（QA）**三个环节解耦，并在每个环节显式地处理信息的**状态角色**（当前、历史、过渡）。

#### 2. 论文提出的方法论：A-TMA

-   **核心思想**：A-TMA 是一个**状态感知覆盖层**，它可以附加在现有记忆系统之上。它不取代宿主系统，而是通过三个模块，在存储、检索和回答三个层面注入状态语义，确保系统根据查询请求的状态返回正确的信息。
-   **关键技术细节**：
    -   **1. 银行层面的状态维护 (Bank Level)**：
        -   **目的**：保持历史的同时，防止过时事实被当作当前事实使用。
        -   **机制**：引入**Sentry**和**Judge**两个组件。当新记忆到来时，Sentry快速筛选出可能涉及同一状态变量的新旧候选对。对于可疑对，Judge进行深度审计，判定其关系（如取代、过渡、共存），并更新记忆的状态标签（active/superseded/transition）和关联链接。
    -   **2. 检索层面的证据构建 (Retrieval Level)**：
        -   **目的**：确保检索到的证据列表与查询所请求的状态视图一致。
        -   **机制**：首先通过一个**规则查询分析器**推断查询所请求的状态视图（vq）。然后，在宿主系统检索结果的基础上，通过状态链接进行扩展，形成一个候选池。最后，使用一个**有界控制器**来对证据进行重新排序和选择，优先展示与查询状态视图最匹配的证据。
    -   **3. 问答层面的状态条件化 (QA Level)**：
        -   **目的**：防止答案模型面对多条不同状态的证据时，推断出错误状态。
        -   **机制**：在将证据输入答案模型前，进行**标签化序列化**。明确为每条证据打上标签（如：`current memory`, `historical memory`, `transition memory`），并在提示中强制答案模型根据查询请求的状态和这些标签进行回答。
