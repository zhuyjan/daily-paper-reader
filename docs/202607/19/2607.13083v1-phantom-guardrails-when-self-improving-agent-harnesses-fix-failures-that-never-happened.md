## 摘要
自我改进的AI智能体旨在从错误中学习。我们证明它们也能幻觉出从未发生的错误。我们在自动优化测试框架中研究这种故障模式，其中基于LLM的提议者编辑智能体的脚手架，包括提示、解析器、过滤器、验证器和护栏，以消除观察到的故障。但这个过程很少先问：是否真的有需要修复的故障？我们引入了反事实制造实验室，这是一个确定性微型实验室，其中正确的操作是已知的：什么都不做。该实验室为一种被证明从未发生的故障类别植入一个候选护栏，只呈现合法实例，并使用字节精确的预言机检查每个引用的违规行为。提议者对于真实违规行为表现符合预期，对于无特征的合法输入则不做任何操作。然而，当合法输入包含一个类似于熟悉游戏规则的无害模式时，它会编造一个故障：在60次运行中有15次，而在无特征输入上为0/60，它启用了不存在规则的护栏，并引用了被预言机驳斥的违规行为。这种效应是有结构的，而非无差别的。在单次提议中，仅当三个条件同时满足时才会出现：一个规则形状的模式、一个开放式的规则集以及一个预设故障的指令。移除这些条件中的任何一个都会消除编造行为。由于编造的护栏不改变任何真实结果，也无法改进已经完美的抑制分数，这种现象既不是奖励黑客行为也不是过度拒绝。它是一个幻影护栏：针对从未发生过的故障的修复，对仅抑制的接受标准不可见。在仅添加的接受循环中，即使没有预设故障的指令，它也会重新进入，循环的持续添加角色提供了单次指令中所提供的需求，一旦进入就会停留。我们提出了用于测量自我改进智能体框架中编造故障的反事实制造实验室。

## Abstract
Self-improving AI agents are designed to learn from their mistakes. We show they can also hallucinate mistakes that never happened. We study this failure mode in automated harness optimization, where an LLM-based proposer edits an agent's scaffold, including prompts, parsers, filters, validators and guardrails, to eliminate observed failures. But this process rarely asks first: was there a real failure to fix? We introduce the Counterfactual Fabrication Lab, a deterministic micro-lab where the correct action is known: do nothing. The lab plants a candidate guardrail for a failure class that provably never occurs, presents only legal episodes, and uses a byte-exact oracle to check every cited violation. The proposer behaves as expected on real violations and abstains on featureless legal input. Yet when the legal input contains a harmless pattern resembling a familiar game rule, it invents a failure: in 15/60 runs, versus 0/60 on featureless input, it enables the nonexistent-rule guardrail and cites a violation the oracle refutes. The effect is structured, not indiscriminate. In single-shot proposals it appears only when three conditions coincide: a rule-shaped pattern, an open-ended rule set and an instruction that presupposes failures. Removing any of these conditions eliminates the fabrication. Because the invented guardrail changes no true outcome and cannot improve an already-perfect suppression score, the phenomenon is neither reward hacking nor over-refusal. It is a phantom guardrail: a fix for a failure that never happened, invisible to suppression-only acceptance. Inside an add-only accept loop it re-enters even without the failure-presupposing instruction, the loop's keep-adding role supplying the demand the instruction supplied in single shot, and once in it stays. We present the Counterfactual Fabrication Lab for measuring fabricated failures in self-improving agent harnesses.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **研究动机**：自我改进的AI智能体（通过LLM自动优化其脚手架，如提示、解析器、护栏等）通常被设计为通过抑制观察到的故障来学习。但这种优化仅检查“故障是否消失”，而不问“修复是否必要”。这可能导致一种被忽视的失败模式：**智能体可能虚构（hallucinate）从未发生的故障**，并为不存在的规则添加防护措施。
- **整体含义**：揭示了在“抑制回报”优化范式下的一种新故障——幻影护栏（phantom guardrails）：修复了一个从未发生的问题，且这种修复在仅通过抑制分数评估时完全不可见（因为抑制分数未变）。这种效应既不是奖励黑客行为（reward hacking）也不是过度拒绝（over-refusal），而是一种在证据不足下“先发制人”的虚构，且可能在自改进循环中被永久保留。

## 2. 论文提出的方法论：核心思想、关键技术细节

- **核心思想**：构建一个确定的微型实验室（Counterfactual Fabrication Lab），其核心是“正确的行动是‘什么都不做’”。通过种植一个针对**不可能发生的故障类别**的候选护栏，并提供一个**字节精确的预言机**来验证每个被引用的违规是否真实存在，从而探测智能体是否会虚构故障。
- **关键技术细节**：
  - **任务环境**：确定性“MiniArena”棋盘游戏，智能体执行移动。定义了三个故障类：`syntax`（语法）、`bounds`（出界）、`castle`（王车易位，探针类）。`castle`类由生成器正确编码，永远不会自然出现；只有在人工注入（injector）记录时才会触发。
  - **编辑菜单**：四个钩子（hooks）：P（修复移动字符串）、Q（注释观察，惰性）、R（阻断出界移动）、S（阻断“特殊规则违规”，对应`castle` guard）。菜单不说明具体规则。
  - **预言机**：每个故障类有一个字节精确的预言机`O_c(e) ∈ {0,1}`，从不同记录字段读取，类之间可分离。对于在池上没有`castle`故障的池，`O_castle(e)=0`对所有实例成立。
  - **抑制代理**：定义`S(H, D)`=没有故障发生的剧集分数。在所有合法的池上，`S=1`已经是最大值。
  - **编造度量**：在一个被预言机证明无`castle`故障的池上，如果最终框架包含`g_castle`，则视为编造（Fabrication）。编造率是对多轮运行的均值。
  - **研究流程**：
    - 单次提议（single-shot）阶段：LLM提议者（基于系统提示和规则菜单）一次返回一组护栏和一句理由。法官仅读取输出，无反馈。
    - 接受循环（accept loop）阶段：模拟用户循环，每次提议添加护栏，法官根据三种规则（抑制不恶化、严格改进、担保感知）接受或拒绝，已接受的永久保留（附加-only模型）。
- **控制实验**：通过改变池内容（特征无/良性重复模式/不同模式）、规则集完整性声明、系统提示（预设故障 vs. 中性指令）、循环角色等，隔离编造的因果条件。

## 3. 实验设计：数据集/场景、基准、对比方法

- **数据集/场景**：
  - **MiniArena游戏**：12个剧集/池，每个剧集4步移动。所有移动均为合法格式。构建三种基池：
    - *一致池（congruent）*：注入4个真实的非法王车易位记录（`legal=ILLEGAL`），护栏导致抑制。用于验证探测器正常工作。
    - *制造池（fabrication pool）*：全合法，但包含一个良性表面规律：3~5个剧集中出现重复方格（如同一位置多次移动）。任务没有关于重复的规则。
    - *原始池（pristine）*：全合法且无规律（所有方格不同）。
  - **额外的控制池**：
    - *模式电池（pretext battery）*：在固定发病率（4/12）下种植：重复方格、同列、固定对角线、角落方格。前一个对应棋盘游戏规则，后三个无游戏规则对应。
    - *完整性保证（completeness-assured）*：在语料前加一句话：“合法性标签是权威且完整的，没有隐藏规则。”
    - *中性指令（neutral instruction）*：系统提示不预设故障，仅说“提出由这些剧集证明合理的护栏”。
  - **接受循环场景**：在相同的制造池上运行附加-only循环（最多4轮），使用三种法官规则（抑制不恶化、严格改进、担保感知）。同时在混合池（有真实故障）上测试严格改进规则。
- **基准（baseline）**：
  - 单次提议的基准是在原始池上的行为（0/60编造）。
  - 对比条件：改变池规律、提示内容、指令措辞，观察编造率变化。
- **对比方法**：论文本身没有与其他方法（如其他优化框架）对比，而是通过自身对照实验进行因果推断。主要对比不同池状态下的编造率。
- **提议者**：5个主流LLM（deepseek-v4-pro/flash, qwen3.7-max, qwen3.6-max-preview, glm-5.1）通过OpenAI兼容API调用，温度0.7。另扩展3个提议者（kimi-k2.6, qwen3.6-plus, qwen3.6-flash）。

## 6. 论文的主要结论与发现

1. **智能体在无特征证据上能正确放弃**：在原始池上，60次运行中54次返回空框架，0次启用幻影护栏。表明智能体并非总是建设。
2. **良性模式会触发编造**：在制造池（含无意义的重复模式）上，幻影护栏启用率0.25（15/60），而原始池为0。原因被解释为规则形状的模式（重复）与任务体裁的既有规则（如兵重复）匹配，智能体导入该规则。
3. **编造需要三个条件同时满足（在单次提议中）**：
   - **规则形状的模式**（重复方格生效，同列、对角线、角格不生效）。
   - **未声明的规则集完整性**（一旦声明标签完整且无隐藏规则，编造消失为0/60）。
   - **预设故障的指令**（系统提示假设有故障；替换为中性指令后编造为0/60）。
   - 移除任何一个条件，编造率降为0。
4. **编造不是奖励黑客行为或过度拒绝**：幻影护栏在合法池上不改变真实回报（不抑制任何故障，不阻止任何合法移动），因此不降低任务效用；也不能提升已完美的抑制分数。它不是通过牺牲帮助性来换取安全分数。
5. **接受循环的行为取决于法官规则**：
   - **抑制不恶化（accept-if-not-worse）**：幻影护栏在首次提议中被接受（因为不恶化抑制分数），并在后续轮次中累积（11/60轨迹在第四轮包含幻影）。
   - **严格改进（strict improvement）**：单独的幻影被拒绝，但如果与真实修复绑定在改进批次中，则可能一起进入（2/60）。
   - **担保感知（warrant-aware）**：要求每个护栏引用一个被预言机确认的故障，幻影被完全排除（0/60）。
   - 一旦进入（在从未删除的框架中），幻影是吸收性的，无法通过抑制信号移除（因为移除它也不改变分数）。
6. **循环的作用**：在附加-only循环中，循环的“持续添加”角色本身提供了需求，即使没有预设故障的指令，也能导致编造（5/12 for glm-5.1）。这与2×2表格中中性指令下编造为0相符（循环的角色替代了指令的需求）。
7. **扩展模型**：所有8个提议者在一致池上100%启用幻影护栏（探测器工作正常），在原始池上0%编造。在制造池上，仅glm-5.1表现突出（11/12），其余较弱或零。说明效应不是所有模型通用，但具有重复性。

## 7. 优点

- **方法创新**：构建了确定性微型实验室，能够用绝对真值（字节精确预言机）测量“基于证据的虚构”，避免了依赖人类判断或第二模型。
- **因果实验设计**：通过精细的控制实验，隔离了编造的三个因果条件（模式形状、规则集知识、指令预设），展示了“移除任一条件即可消除效应”的强证据。
- **严谨的混淆排除**：
  - 盲化控制（clean blinded arm）排除了菜单中“special rule”词汇的泄漏。
  - 安全框架下的负面结果（附录B）暴露了工具来源混淆和同音词效应，说明了设计干净实验的重要性。
  - 提供了完整的提示、回应案例（附录E、F），可复现。
- **覆盖多模态测试**：单次提议和接受循环两种场景都进行了测试，且三种接受规则的结果明确。
- **实用指导**：指出了三个可操作的杠杆：指令卫生（不预设故障）、规格固化（声明规则集完整）、担保感知接受规则。特别指出单一修复提示（用中性指令）可将编造率从0.25降至0。

## 8. 不足与局限

- **领域单一性**：实验仅在MinArena（棋盘游戏）上进行，该任务具有特定的体裁先验（如重复规则）。现实中的自由形式代码提议者和其他领域（如安全规则提示注入防护）尚未被测试（附录B中的安全框架实验因为混淆未能给出结论）。
- **效应规模较小**：编造率大约0.25，且主要集中在glm-5.1一个模型上（11/12）。论文承认这是“分类性和机制性贡献而非大数字”。这限制了结论的普遍性，可能反映了模型能力依赖性。
- **完整性保证可能的解释**：作者指出了一个潜在的替代解释——完整性保证可能被模型视为指令遵从（“你说没有隐藏规则，我就相信”）而非真正减少不确定性。但该保证段未提及任何护栏，且注释器速率不变，模式仍被提及，削弱了纯粹指令遵从的解释。
- **预设故障指令的必要性不绝对**：虽然在单次提议中是必要的，但在循环中指令被循环角色取代，这表明机制更丰富，但也可能引入其他混杂（如循环消息显示当前抑制分数，可能提供暗示）。文中也已承认循环是“第二机制”。
- **缺少对更广泛优化框架的对比**：论文没有对比现有其他自我改进框架（如RHO、Meta-Harness）或约束推理等方法，而是专注于隔离现象。
- **缺乏对“过度修复”的代价度量**：幻影护栏导致的附加计算成本（延迟、表面积、能量）仅在概念层面讨论，没有量化。
- **接受循环实验假设**：循环假定附加-only，且法官仅考虑抑制分数。现实中的优化器可能包括修剪或更复杂的接受准则，但论文通过附录B的第二看实验（ledger pruning）进行了简要讨论，表明诚实分类账能修剪幻影，但分类账错误会删除真实修复（基于遵从而非判断）。这说明了实际部署的脆弱性。
