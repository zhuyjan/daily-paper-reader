## 摘要
训练API调用的大语言模型（LLM）智能体需要大量高质量的轨迹。然而，大规模收集此类数据通常需要完全实现的环境，包括可执行的API和预填充的真实后端数据库，这成为可扩展性的主要瓶颈。为了克服这一问题，我们提出了一种无环境的合成数据生成方法，该方法利用LLM作为即时数字世界模型。仅给定API规范，我们的方法生成模拟智能体与有状态环境之间交互的轨迹。具体来说，LLM首先生成可使用所提供API解决的多样化任务。然后，教师智能体迭代地解决每个任务，同时LLM模拟器根据任务上下文和模拟历史生成连贯的合成API响应。最后，LLM评判器过滤轨迹以确保最终数据集的质量。我们在具有挑战性的AppWorld和OfficeBench基准上评估了我们的方法，这些基准包括信息检索和状态更改任务。在我们的合成数据上微调模型带来了显著的性能提升，这表明无需任何可执行环境即可生成用于API调用智能体的有效监督信号。我们的结果确立了基于LLM的API模拟作为一种实用且可扩展的解决方案，用于跨不同API生态系统训练智能体。

## Abstract
Training API-calling large language model (LLM) agents demands massive amounts of high-quality trajectories. However, collecting such data at scale typically requires fully implemented environments with executable APIs and realistic, pre-populated backend databases, creating a major bottleneck for scalability. To overcome this, we propose an environment-free synthetic data generation approach that leverages LLMs as on-the-fly digital world models. Given only API specifications, our method generates trajectories mimicking interactions between an agent and a stateful environment. Specifically, an LLM first generates diverse tasks solvable with the provided APIs. A teacher agent then iteratively solves each task while an LLM simulator generates coherent synthetic API responses conditioned on the task context and simulation history. Finally, an LLM judge filters the trajectories to ensure the quality of the resulting dataset. We evaluate our approach on the challenging AppWorld and OfficeBench benchmarks, which include both information-retrieval and state-changing tasks. Fine-tuning models on our synthetic data yields significant performance gains, demonstrating that effective supervision for API-calling agents can be generated without any executable environment. Our results establish LLM-based API simulation as a practical, scalable solution for training agents across diverse API ecosystems.

## 二、方法论：核心思想、关键技术细节

### 核心思想
利用LLM作为API模拟器（数字世界模型），替代真实环境来提供状态感知的反馈。整个管道由三个独立但衔接的阶段组成：

### 阶段1：任务合成（Task Synthesis）
- **桶化生成**：将任务空间划分为组合网格（难度×动作类型×任务焦点×应用数×API范围），随机顺序处理每个桶，生成任务。
- **逆频率采样**：维持每应用和每API的使用计数，优先选择未充分代表的应用/API，保证覆盖平衡。
- **任务过滤**：LLM评判器检查任务是否可解、格式正确且符合桶配置。
- **任务重写**：将步骤冗长的任务压缩为自然、意图级别的用户请求，并再次由评判器验证。

### 阶段2：轨迹合成（Trajectory Synthesis）
- **教师代理**：由LLM（GLM-5.1-FP8）充当，迭代调用API解决每个任务。
- **LLM API模拟器**：为每次API调用生成响应，条件包括：
  - 完整API规范
  - 调用参数
  - 任务上下文
  - 同应用的历史调用记录（限制历史长度）
  - 虚拟用户信息（姓名、邮箱、电话）
  - 当前日期时间
- **模拟器四大规则**：
  1. 数据一致性：跨调用保持状态连续（如歌曲与艺术家映射不变）。
  2. 数据多样性：返回结果中混合任务相关与无关项（约30-50%相关）。
  3. 数据真实性：字段值尊重数值范围、唯一ID、时间戳相对当前时间。
  4. 模式合规：严格匹配API规范中的响应模式（成功/失败）。
- **质量检查**：
  - 程序化输入验证（缺失参数、类型错误直接返回错误消息）。
  - 输出模式验证 + LLM评判器语义验证（仅对GET API进行）。
  - 固定次数重试循环。

### 阶段3：轨迹过滤（Trajectory Filtering）
- 使用Gemini-3.1-Pro作为LLM评判器，对每条轨迹进行多次评判，仅保留多数正判决的轨迹。

## 六、主要结论与发现

1. **环境无关的有效性**：ESAT生成的纯合成数据在AppWorld上使Qwen3-8B从零样本21.1%提升至64.9%（Test-N），超过使用真实环境数据AWT（55.7%）的性能。在OfficeBench上最高提升60.5%。
2. **强泛化能力**：仅用52个合成应用生成的数据（ESAT-S52）即可在未见AppWorld API上取得超越真实环境数据的效果，证明模型学到了通用的API调用技能。
3. **状态一致性模拟**：模拟器在93.7%的调用中保持状态一致，但长输出（>2K tokens）失败率达23%。
4. **知识蒸馏成功**：小模型（4B-8B）经ESAT数据微调后超过GPT-4o（48.8%）和Nemotron-3-120B（51.8%）等大模型，Qwen3.5-27B接近教师模型GLM-5.1-FP8性能。
5. **评判器质量关键**：Gemini-3.1-Pro作为轨迹评判器显著优于GLM，能有效筛选高质量数据。
6. **合成应用设计可扩展**：52个合成应用覆盖10大领域，API覆盖率99.6%，证明方法可轻松适应新API生态。

## 七、优点

1. **高度可扩展**：仅需API规范，无需构建真实环境或编写任务，数据生成成本大幅降低。
2. **支持有状态读写API**：模拟器能够处理跨写API的状态变化，这是多数现有模拟方法（如ToolAlpaca、ToolACE）不具备的。
3. **状态保持机制**：通过保留每App的历史记录和严格的重试验证，模拟器有效减少状态漂移。
4. **覆盖平衡策略**：逆频率采样和桶化生成确保任务覆盖所有API和应用，避免数据偏斜。
5. **自动质量过滤**：多阶段过滤（任务重写、模拟器双验证、轨迹评判）保证最终数据集的高信噪比。
6. **实验设计全面**：跨多个模型家族和规模、两个不同复杂度的基准、充分的消融，结果稳健。

## 八、不足与局限

1. **长输出模拟失败率偏高**：当输出超过1000 tokens时失败率升至8-23%，可能限制需要长内容返回的任务（如完整文档内容）。
2. **对评判器模型依赖性**：轨迹过滤严重依赖Gemini-3.1-Pro，而较弱的评判器（如GLM）反而降低性能，实际应用中需要足够强的LLM作为评判器。
3. **缺乏向后兼容性测试**：所有生成固定于特定LLM（GLM系列、Gemini），未验证使用不同模型作为模拟器/评判器时的鲁棒性。
4. **人工评估规模小**：仅200条轨迹，且全部来自AppWorld，未在OfficeBench上验证一致性。
5. **模拟失败案例分析不足**：虽然报告了失败类型分布，但未详细分析失败对下游模型性能的具体影响（如是否导致微调后出现特定类型错误）。
6. **应用限制**：假设所有API规范已知且结构清晰，对于动态变化的API或非标准接口（如自定义内部工具）可能不适用。
7. **计算开销未计量**：论文未提供完整的GPU小时数或合成阶段的计算成本，难以评估实际部署的资源需求。
