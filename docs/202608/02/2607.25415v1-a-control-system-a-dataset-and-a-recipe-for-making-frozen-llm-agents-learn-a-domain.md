## 摘要
生产级LLM智能体越来越多地由一个冻结模型加上一个外壳（harness）组装而成：提示模板、工具集、记忆/检索层、规划策略和验证策略。2026年的两个系统，Meta-Harness（Lee et al., 2026）和HyperAgents（Meta AI, 2026）表明，这个外壳本身可以被一个智能体提议者优化甚至自我重写——但代价是昂贵的代码搜索循环或不受约束的自我修改代码，这两者都无法审计，也无法用于完全黑盒的模型API。我们采取一个更窄、更受约束的立场：将外壳视为一个小的、固定的、人类可读的动作空间，并在线使用经典的样本高效强化学习（一个ε-贪心上下文赌博机和REINFORCE）来学习其上的策略，根据多目标奖励（任务成功、验证器分数、策略合规性、成本、延迟和未支持声明惩罚）进行评分。我们使用DSPy（Khattab et al., 2024）实例化这个控制系统，既作为上下文组装器，也作为最强的非自适应基线（DSPy BootstrapFewShot静态提示）的来源，并在三个可验证的任务领域——工具使用工作流、代码生成（HumanEval）和多跳检索问答（HotpotQA）——以及两个模型提供商（本地Ollama模型和AWS Bedrock）上对其进行评估。我们发布了外壳控制系统代码、跨领域可验证任务套件、训练期间的完整轨迹/奖励分解日志，以及一个与提供商无关的部署配方，用于将其应用于新组织的领域和验证设置。

## Abstract
Production LLM agents are increasingly assembled from a frozen model wrapped in a harness: a prompt template, a tool set, a memory/retrieval layer, a planning strategy, and a verification policy. Two 2026 systems, Meta-Harness (Lee et al., 2026) and HyperAgents (Meta AI, 2026), show that this harness can itself be optimized or even self-rewritten by an agentic proposer -- at the cost of either an expensive code-search loop or unconstrained self-modifying code, neither of which is auditable or usable with a fully black-box model API. We take a narrower, more constrained position: treat the harness as a small, fixed, human-legible action space and learn a policy over it online with classic sample-efficient reinforcement learning (an $ε$-greedy contextual bandit and REINFORCE), scored against a multi-objective reward (task success, verifier score, policy compliance, cost, latency, and an unsupported-claim penalty). We instantiate this control system with DSPy (Khattab et al., 2024) as both the context assembler and the source of the strongest non-adaptive baseline (a DSPy BootstrapFewShot static prompt), and evaluate it across three verifiable task domains -- tool-use workflows, code generation (HumanEval), and multi-hop retrieval QA (HotpotQA) -- and two model providers (a local Ollama model and AWS Bedrock). We release the harness-control-system code, the cross-domain verifiable task suite, the full trajectory/reward-decomposition logs from training, and a provider-agnostic deployment recipe for applying this to a new organization's domain and verification setup.

## 一、核心问题与研究动机

**背景**：生产环境中的LLM智能体，通常并非仅由一个模型构成，而是由一个**冻结的模型**外加一个**外壳（harness）** 组合而成。这个外壳包括提示模板、工具集、记忆/检索层、规划策略和验证策略。2026年的两篇工作（Meta-Harness、HyperAgents）表明，外壳本身可以被优化甚至被自我重写，但这些方法存在显著问题：
- Meta-Harness：依赖昂贵的智能体代码搜索循环。
- HyperAgents：运行不受约束的自我修改代码。

两者均**不可审计**，且**无法在纯黑盒模型API（如防火墙后的chat-completions接口）环境下使用**。

**作者立场**：本文提出一种更受约束、更实用的方案——将外壳视为一个**小规模、固定、人类可读、可枚举的动作空间**，通过**经典且样本高效的强化学习**（ε-greedy上下文bandit和REINFORCE）在线上学习该空间上的策略。由此换来Meta-Harness和HyperAgents不优化的三个特性：
1. **可审计性**：每个控制器决策都是少数几个事先审查过的命名配置之一，回归可归因于具体杠杆，而非难以追查的代码差异。
2. **黑盒兼容性**：控制器无需代码执行权限，适用于任何纯chat-completions端点。
3. **多目标奖励**：与单一任务准确率不同，明确将合规性和未支持声明率作为一级信号。

## 二、方法论

### 2.1 核心思想

将LLM智能体的外壳（harness）分解为**六个离散杠杆**，构成一个固定且可枚举的动作空间。通过在线强化学习（bandit/REINFORCE）在这个空间中搜索最优配置，以多目标奖励函数进行评分。

### 2.2 外壳动作空间定义

六个离散杠杆及取值如下：

| 杠杆 | 可选值 |
|------|--------|
| 提示风格（prompt style） | direct, structured, reflective |
| 工具策略（tool policy） | never, when needed, always |
| 记忆策略（memory policy） | none, similar successes, successes and failures |
| 规划策略（planning policy） | none, brief plan, plan and revise |
| 验证策略（verification policy） | none, final check, stepwise |
| 最大步数（max steps） | 2, 4, 6 |

总配置数：**3⁵ × 3 = 729** 种。

### 2.3 DSPy作为上下文组装器

- 根据任务与所选配置，构建DSPy Signature（指令随提示风格变化）。
- 由规划策略选择对应的DSPy Module（Predict、ChainOfThought、或两遍draft-then-revise模块）。
- 记忆策略控制从轨迹库中附加多少历史轨迹作为few-shot示范。
- 工具策略控制工具/段落暴露程度。
- 验证策略可选地增加一次廉价自检调用。

同一个组装器同时支撑在线控制器与静态基线，确保公平对比。

### 2.4 奖励函数

\[
R = w_s \cdot \text{success} + w_v \cdot \text{verifier score} + w_c \cdot \text{compliance} − w_u \cdot \text{unsupported claims} − w_$\cdot \text{tokens}/1000 − w_\ell \cdot \text{latency}/1000
\]

各领域由确定性验证器打分：
- **代码生成**：执行官方单元测试。
- **工具使用**：与模拟后端的状态diff比对。
- **检索QA**：与标准答案做精确匹配，token-F1作为较软的验证分数。

### 2.5 对比控制器

1. **Random**：对729种配置均匀随机采样，作为下界。
2. **ε-greedy上下文bandit**：基于任务特征向量的线性价值估计，采用**乐观初始化**避免冷启动陷阱。
3. **REINFORCE**：729个动作上的softmax策略，线性特征logits，带熵正则和移动平均基线。
4. **DSPy-static**：固定配置（结构化提示、按需工具/检索、简要计划、最终检查验证），用DSPy BootstrapFewShot针对每个（模型、领域）的少量标注子集优化一次示范，作为**最强的非自适应基线**。

## 六、主要结论与发现

### 6.1 核心发现（出乎意料）

**DSPy优化的静态基线在所有领域、所有模型（包括更强的Sonnet）上，均匹配或击败了在线的自适应控制器（bandit和REINFORCE）**，而且通常以显著更低的token成本达成。例如：
- 工具使用 / Bedrock Haiku：DSPy-static以96%成功率和285 tokens/episode远优于REINFORCE的62%和680 tokens。

### 6.2 原因分析：样本效率差距，而非天花板

- 729个动作的配置空间需要Ω(M)样本才可能样本高效；主矩阵的25-60 episodes远不够。
- 补充实验：300-episode运行（5-12倍预算）下，bandit与REINFORCE虽缓慢上升但仍停在0.61-0.65区间，显著低于DSPy-static的0.96——表明这是一个实际瓶颈而非运行时长不够。
- **解读**：从均匀先验出发在线学习729配置空间，不如现有的、受指标引导的静态搜索（BootstrapFewShot）样本高效。因此REICIPE.md建议**先用静态基线引导初始化**，再部署在线控制器——这一顺序在实践预算下是"承重墙"级别的建议。

### 6.3 工程经验教训

1. **冷启动陷阱**：零初始化Q值 + numpy.argmax确定性平局打破 → bandit初始动作恰好是无法解决工具任务的配置。修复：乐观初始化 + 随机平局打破。
2. **崩溃隔离缺口**：Sonnet的plan-and-revise在coding任务上偶发token耗尽导致解析失败，一个episode崩溃带垮整个job。修复：每个episode独立try/except，解析失败计为正常失败的episode。
3. **度量陷阱**：DSPy的LM磁盘缓存命中后返回空usage字典，导致token欠计。修复：字符长度回退估算。
